# 第一次多角度代码审查(2026-11-01)

对当天新写的接单层、迭代驱动、控制面 SSE、节点 diff 路由和 React 工作台做了一次 5 个视角的审查(正确性、安全、迭代驱动、控制面与节点、前端),每条发现由两个独立的"反驳者"复核,54 条发现里 40 条站住。全部修在同一天的提交里;这里记下值得记住的几类。

## 真缺陷(修了)

| 处 | 问题 | 修法 |
| --- | --- | --- |
| 迭代驱动 build() | 自检以 root 跑 Python,把 `__pycache__` 和临时 tar 打进了候选层,之后每代的 diff 都被污染 | 自检 `-B`、打包前清缓存与临时文件;untar 忽略字节码 |
| 接单 receive() | 人在 Thread 里说"停"永远到不了 Eval:有在途工单时消息被扇出到 inbox;正则也不认带连字符的 `@cairn-bot` | 名单内的人说停 → 直接停掉在途工单并记一条 stop Decision;正则改成 `(@[\w.-]+\s*)?(stop|停止|停)` |
| 接单 _execute | 人的回答(kind = answer)没进 ticket 文本,恢复派工只带原始请求,harness 把同一个问题再问一遍 | trigger 与 answer 都进文本,答案标明来自谁;派工时以到达时间为身份标记"已送达",等槽位期间到的消息不会被盖掉 |
| 接单 _run_assignment | 基础设施失败不重试、不回帖 | 同一人工输入之后最多三次,退避 5 / 30 / 120 秒,第三次后报 failed 并回帖 |
| 接单 _report | 第二次 ready 对已有 PR 的工单再开一个 PR,409 后变 blocked;deliverable 以基线提交为准,恢复派工没新提交也算有交付 | 已有开着的 PR 就只推分支并回一句"已更新";harness 以派工开始时的 HEAD 判断有没有新提交 |
| 接单 relay | agent 的分支会开 PR,而 CI 对 PR 触发、runner 有宿主 docker socket:一个改 `.gitea/` 或测试文件的 PR 就能在 runner 上以宿主权限跑代码 | CI 只对 main 的 push 触发;中继拒绝触及 `.gitea/`、`ci/`、`run-node.sh`、`node/Dockerfile` 的补丁,转为 blocked 让人手动处理 |
| 接单重启 | 运行中的派工永远 running,后续消息没人送达;Eval 的 running 戳卡死线程 | 启动时把 pending/running 派工标 ended 并销毁沙箱,给有未送达人工输入的开着工单重新派工;running 超过 600 秒视为失败,三次后记 unavailable |
| 接单 revalidate | 准入表格子来的 Mandate 恢复时无条件通过 | 用原始强度重跑 Gate |
| 节点 h_diff | 查询串没解码,前端的 `cwd=%2Fwork%2Frepo` 永远 400;`git status` 粘在 diff 后面 | `parse_qsl` 解码;`status` 单独返回;diff 对合并基 |
| 控制面 | SSE 带 `?token=` 但只认 Authorization 头,设了 CP_TOKEN 就永远 401;经转发 fork 出的克隆没登记路由;上游在响应头发出后失败会写出第二个响应;node / sandbox 摘要看不到暂停、失败 | 只对 `/events/stream` 接受查询串令牌并常量时间比较;fork 单独处理并登记克隆,每分钟对账一次;头发出后出错只关连接;摘要含存活、错误与各节点计数 |
| 评测器 | 基础设施重试丢掉前几次 agent 阶段的费用 | 失败的验证阶段把 agent 费用挂在异常上,成功的那次累加 |
| 导入器 | Polyglot 只拷 `*_test.py`,带辅助模块的题(paasio)参考解都过不了;WorkBuddy 的 `allowed_write: ["."]` 永远不匹配,每次运行都带一条越界写信号 | 拷 verify/ 下全部文件;`./`,并且 `path_allowed` 把 `.`、`./`、空当作全放行 |
| 前端 | 导航徽标在渲染里读 `getState()` 不订阅,数字不更新;路由参数 `decodeURIComponent` 无保护,一个坏转义整页白屏;轮询失败把已有数据清空;SSE 断线后 `live` 不复位;终端会话在 StrictMode 下泄漏;执行面板卸载后继续消费流,`stderr` 事件名写错;文件面板用 `$1` 传路径根本不工作;策略规则没冒号的行被截断保存 | 徽标改成选择器由 NavItem 订阅;解码加 try 与错误边界;失败保留旧数据只显示横幅;连接状态回调;会话打开后检查是否已卸载;卸载即中止;事件名 `err`;改用 `FC_PATH`;规则行校验 |
| 设计检查 | 漏掉 `text-4xl`、任意单位、CSS `font-size`、调色板类名、插件间直接导入 | 规则补齐 |

## 没修、记下来的

- 控制面在共享机上没有令牌就裸跑在 127.0.0.1:18700:同机的其他登录用户能创建沙箱、执行命令。CI 的各套件、工作台、评测器都经控制面,统一加令牌要改一圈;先记在 010 里,下一次动控制面时一起做。
- 接单层 HTTP API 本身无鉴权(同上,经控制面转发,控制面有令牌时它才有)。
- 一个 SSE 客户端一轮一次轮询,多个标签页就多份;以后改成一处轮询多处扇出。
- `addressed` 是子串判断("@cairn-bot" 出现在引用里也算);等真实流量再定。
