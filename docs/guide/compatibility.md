# 版本与兼容承诺

**现状**:还没有发布过带版本号的稳定版;下面是**打算**怎么做,和现在的差距写在最后。接口合同是 [CONTRACT.md](../../CONTRACT.md),变化记在 [CHANGELOG](../../CHANGELOG.md)。

## 版本号

- 沙箱云(控制面 + 节点 + SDK)用一个版本号,`MAJOR.MINOR.PATCH`;SDK 的版本跟着它(`cairnsandbox.__version__` 现在是 0.1.0)。
- agent 层单独编号,不影响沙箱云的承诺(两层之间只有一道接缝,002)。
- 0.x 期间接口可以变,但每次变化都进 CHANGELOG 的"已知不兼容";1.0 起按下面的规则。

## 1.0 之后的承诺

| 变化 | 规则 |
| --- | --- |
| 加端点、加请求里的可选字段、加响应里的字段 | MINOR,不算破坏;**调用方必须忽略不认识的响应字段** |
| 改字段含义、改状态码、删端点或字段、把可选变必填 | MAJOR |
| 废弃 | 先在 CHANGELOG 与响应头 `Deprecation` 里标出,至少保留一个 MINOR 再删 |
| 错误信息文字 | 不承诺;用状态码与 `error` 前缀判断 |
| 审计与 `/metrics` 的字段 | 只加不改;指标名一经发布不改 |
| E2B 形状的口 | 跟 E2B 的 REST 走;E2B 改了我们跟,跟不上的字段写进兼容矩阵([api/e2b.md](api/e2b.md)) |
| 节点接口(合同 §2) | 内部接口,控制面与节点同版本部署,不对外承诺 |
| 升级顺序 | 先节点再控制面再 SDK;控制面向前兼容上一个 MINOR 的节点 |

## 和现在的差距

- 没有发布流程、没有打 tag、没有 `Deprecation` 头;
- 合同里的字段还没有"稳定 / 实验"标注;
- 没有兼容性测试(用上一个版本的 SDK 打当前控制面)。

这三条做完才算可以宣布 1.0。
