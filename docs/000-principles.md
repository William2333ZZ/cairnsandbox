# 000 原则

这个项目是一个平台,也是一种让 agent 自我改进的方式。它的核心原则:

**沙箱里产生的一切都不可信;可信的只有在沙箱之外测得、记录、强制的东西。**

agent 会改写自己的 harness,所以它说的、算的、报的分数都可能是它改出来的。平台的每个部件都按这条判断:一个度量、一个限制、一次晋升,只要它依赖沙箱内的代码诚实,就不成立,要换成沙箱外的事实。

## 由此对系统

- **边界靠权限,不靠约定。** 不可变的部分(内核、运行时、评测器)与可变的部分(harness)由用户、只读挂载、Landlock、宿主侧网络规则和成本上限隔开。一个"请不要改这里"的注释不是边界。
- **每一层都是配方加产物。** 内核、系统、运行时、解释器、harness、工具链、任务环境全部内容寻址,可以回滚;机器上没有手工装出来的状态。
- **度量在沙箱之外。** 成本来自模型代理,网络来自宿主规则,事件来自运行时的只追加日志,分数来自独立的验证沙箱。agent 自报的数字只作参考。
- **凭证不进沙箱。** 沙箱拿到的是限额、可撤销的令牌;模型密钥、代码托管账号、存储凭证都留在宿主侧,由中继代为动作。
- **评测只回答产品问题:** 这个 CairnSandbox 版本把这个用户的事做得更好了吗。任务来自用户自己的工作;通过率在天花板或地板上的任务不进比较;提升小于噪声带不算提升;公开基准只做回归。
- **Python 用来演化,Rust 用来冻结。** 被循环改的东西用解释型语言,改起来便宜;多轮不再变化、要进信任基础的组件重写成 Rust,从此只能人改。
- **先记录,再放开。** 任何新的自动行为先以只记录的方式跑,看记录对了,再让它执行。候选版本先入档,再比较,再晋升;主动接单先 observe,再 auto。

## 由此对设计

- **少概念。** 领域里只有 `002` 列出的那些概念和它们的具体实现。一个新需求变成某个概念的属性,或者 harness 里的一段文本,不变成新概念。
- **少设置。** 一个值对几乎所有部署都合适,就做成默认,不做成设置。用文字能说清的行为放在提示里。
- **不自研已有的东西。** 不写 VMM、不写 OS 内核、不写分布式存储、不从零写 agent 循环;种子来自现成的最小实现。
- **为规模留接缝,不为规模建设施。** 目标是几百到几千个并发沙箱;无状态入口、运行态以节点为准、持久与临时两类沙箱、按需镜像加载这些接缝现在就留,多实例控制面与跨机密度后置。
- **文档有序。** 每篇编号文档只建立在它前面的文档之上;读者不会遇到没有定义过的词。

## 由此对操作者

- **共享的开发机不是你的。** 不做压测,不重启别人的服务,服务只绑定本机回环地址,长构建放后台。
- **密钥只有一个位置。** 模型密钥、代码托管令牌放在仓库之外的密钥目录,以只读文件挂进容器;不进环境变量、不进仓库、不进文档、不进聊天记录。
- **先看证据再动手。** "日志里没有 FAIL"不等于通过;每个测试脚本必须打印正向结果,CI 同时检查退出码和结果行。
- **实验要先说清它回答什么问题。** 通过率全满或全零的任务集上测噪声是花钱买零信息。
