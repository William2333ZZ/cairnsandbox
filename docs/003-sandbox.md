# 003 沙箱与平台

本文描述一台沙箱从创建到销毁经历的宿主侧机制。它建立在 [002 领域模型](002-domain.md) 之上;沙箱侧的八个限界上下文(租户、生命周期、节点、镜像、状态、网络、计量、执行面)在 002 的"沙箱侧的领域"一章,本文按机制写,每个机制归哪个上下文以那一章为准。

## 组成

```
客户端(Web 工作台 / 桌面端)
   │ HTTP
控制面 fc-cp ── 放置、路由、转发(含流式)、迁移、接管、对账、模板分发、静态工作台、/eval 与 /intake 转发
   │ HTTP + bearer
节点代理 fc-node ── 准入、TTL、快照、每 VM 网络、jailer、QoS、层缓存、模板快照与预留池
   └─ 沙箱 = Firecracker microVM(内核 + 基础镜像 + 层 + 可写层)
分块仓库 fc-store ── 内容寻址的层、bundle、内核、基础镜像
模型代理 fc-model ── 每沙箱令牌与预算
```

控制面没有持久运行态:路由、用户、登记的节点放在注册表里(单副本是文件,多副本是一个 Redis),其余从节点对账重建。节点代理是运行态的唯一权威。

## 沙箱的状态

| 状态 | 条件 | 转换 |
| --- | --- | --- |
| creating | 节点已准入,正在放置、拉层、启动、等 daemon 就绪 | → running;→ failed |
| running | daemon 可达 | → paused(显式或空闲超时);→ failed(通道断开、VMM 退出);→ deleted |
| paused | 进程已停,内存链与可写层在盘上;durable 沙箱已发布 bundle | → running(任何请求透明恢复);→ deleted |
| unreachable | 所属节点不可达 | → running(节点回来,对账);→ 由接管在别的节点从最近 bundle 恢复 |
| failed | 创建失败或 VMM 退出,原因可见 | → paused(磁盘尚在)或 deleted |
| deleted | 可写层、快照、bundle 已删 | 终态 |

状态由节点决定并上报;控制面展示节点说的,不自己推断。

## 规格

| 字段 | 含义 | 默认 |
| --- | --- | --- |
| template | 模板名 | 节点的 `DEFAULT_TEMPLATE`(debian-13) |
| class | persistent / ephemeral | 工作台 persistent,评测 ephemeral |
| vcpu, mem | 规格 | 1 vCPU,512 MiB |
| disk | 可写层大小,MiB | 512;离线扩到 16384 |
| layers | 叠在基础镜像上的只读层 id 列表,按序叠放 | 空 |
| network | 模式与白名单 | 关闭,只许模型代理 |
| boot | auto / cold / snapshot | auto:有模板快照就直启 |
| ttl_idle_s, ttl_max_s | 空闲与最长存活 | 工作台 1800 / 无;评测由评测器定 |
| qos | normal / idle | 评测 idle |
| durable | 暂停后是否发布 bundle | persistent 为真 |

规格的组合(模板、规格、层、jail 标志)构成模板键;命中已有模板快照就直启,否则冷启动并在后台建快照。

## 磁盘与层

根文件系统 = 只读基础镜像 + 若干只读层 + 一个可写层,在 guest 内用 overlayfs 叠成一棵树。基础镜像与层被所有沙箱共享,从不复制;可写层每沙箱一个。

| 操作 | 行为 |
| --- | --- |
| 创建 | 基础镜像与层按需从分块仓库取(FUSE,共享缓存,启动画像预取);可写层新建一个空 ext4 |
| pack | 把可写层固化为一个新的只读层,记录名字、大小、来源沙箱;这是构建层配方和 Cairn 候选制品的方式 |
| fork | 以当前状态(或某个快照)为起点新建 n 台沙箱,写时复制,不复制数据;fork 出的沙箱默认 ephemeral,独立计量 |
| 端口暴露 | 沙箱里起的 HTTP 服务经节点反向代理到 /sandboxes/<id>/ports/<port>/…,控制面转发;guest 地址只有节点能连(D39) |
| 提交为模板 | 运行中的沙箱此刻的内存 + 可写层成为一个有名字的模板;新沙箱带 template_key=名字 从它热启动,配置须一致(D37) |
| OCI 镜像成层 | 节点从仓库拉一个镜像(linux/amd64),按序应用 whiteout,把根文件系统用 mkfs -d 写成一个只读层,叠在我们的基础镜像之上;Build 对象记录这次构建(D37) |
| 检查点 | 运行中打一个可回到的点:设备状态 + 一层 Diff 内存(加入链)+ 可写层的稀疏拷贝;guest 只停顿快照那几百毫秒。检查点钉住它引用的内存层 |
| 卷 | 独立生命周期的 ext4 镜像,归项目、住在一个节点;创建沙箱时作为额外的 virtio-block 设备附上并挂到指定路径;一个写者或多个读者,不混;沙箱被放到卷所在节点。harness 目录、仓库缓存、用户数据走这里(D35) |
| 回滚 | 原地回到某个检查点:杀 VMM 进程、把检查点的可写层拷回同一个 inode、从检查点的链恢复;沙箱 id、目录、tap、IP、ticket 都不变,agent 试错一轮失败就回到上一个点继续(D34) |
| 快照 | 内存走 Diff 快照链(只写改过的页),恢复用合并文件或 userfaultfd 按需供页;磁盘靠可写层 |
| 导出 / 导入 | 暂停态沙箱或模板快照打成 bundle 推到分块仓库;稀疏文件的数据区段写进清单,拉取时只写区段内的字节 |
| 迁移 | 源节点暂停并发布,目标节点导入,源节点删除,改路由 |

## 网络

每台沙箱一条策略,由节点在宿主侧用每 VM tap 与 nftables 强制;guest 内没有 DNS,所有出站经出口代理按域名放行。

| 模式 | 适用 | 规则 |
| --- | --- | --- |
| closed | 评测沙箱默认 | 只许模型代理 |
| cache-only | 评测中装包 | 包管理器只能命中读穿缓存;未命中即失败,记为任务失败 |
| allowlist | 工作台默认 | 模型代理、包缓存、搜索服务、用户指定域名 |
| audited | 工作台可选 | 全部经代理放行,每个请求记一条决定(明文 HTTP 到 method 与 path,HTTPS 到 host 与端口);带宽与请求配额未做 |

三种模式之上都可以有 **L7 规则**(按序第一条命中为准,D36):按 scheme / host / method / path 放行或拒绝,放行的规则可以要求代理把节点保险库里的一个凭证加到明文 HTTP 请求上——密钥在节点,不在沙箱,也不在控制面。HTTPS 不做中间人,所以对外部 HTTPS API 的密钥注入只能经专用代理(模型代理就是这样一个)。每台沙箱保留最近 200 条出站决定,节点与控制面都能读。

放宽立即生效需要审批,收紧立即生效。搜索与抓取是沙箱外的服务,沙箱里只有调用它们的工具。沙箱之间永远不互通。

## 节点

| 机制 | 做法 |
| --- | --- |
| 准入 | `MAX_VMS` 与 `MEM_BUDGET_MIB`;满了返回 429,控制面换节点重试 |
| 放置 | power-of-two:从有余量、未 cordon 的节点抽两个,按分数取高的(暖池 / 模板快照优先,再看空位与空内存的比例);创建后立即在本地用量上反馈 |
| 优先级类 | interactive(有人在等)有位子就放;batch / background(评测、进化、例行)只放到仍留有余量的节点(默认 2 个空位、1 GiB),默认 qos=be:一波评测不会把人挤掉(D38) |
| cordon / drain | cordon 后不放新沙箱(标志共享给各副本);drain = cordon + 把 persistent 沙箱逐台迁走,ephemeral 的留着到期;balance 把最忙节点的 persistent 沙箱搬去最闲的(D38) |
| jailer | 每 VM chroot、非特权 uid、独立 cgroup;节点容器需要 SYS_ADMIN、SYS_PTRACE、SYS_NICE,关闭默认 AppArmor 与 seccomp |
| QoS | ephemeral 沙箱的 VMM 线程设 SCHED_IDLE;core scheduling 隔离 SMT 干扰 |
| 内存 | 只读层经 virtio-pmem + DAX 共享宿主页缓存;balloon 回报空闲页;Diff 快照链让暂停只写改过的页 |
| 预留池 | `TEMPLATE_POOL` 维持 N 台已联网的热沙箱,创建时命中键就领走,后台补齐 |
| 排空 | SIGTERM 时把运行中的 persistent 沙箱暂停到盘再退出;`run-node.sh` 先 `docker stop` 再重建 |
| 健康 | 每 2 秒上报 VM 数、内存、模板快照、池、uffd 可用性;通道断开或 VMM 退出即标记 failed |

## 控制面

| 职责 | 做法 |
| --- | --- |
| 注册与健康 | 节点来自环境变量或注册接口,轮询健康 |
| 路由 | 沙箱 id → 节点,落盘;所有 `/sandboxes/<id>/...` 转发,流式按块透传 |
| 接管 | 节点不可达时其沙箱显示 unreachable、操作返回 503;evacuate 把它的 durable 沙箱从最近 bundle 导入别的节点 |
| 对账 | 节点回来后:它持有但路由指向别处的沙箱删掉,路由指向它但它没有的清掉,它有而控制面不知道的收编 |
| 模板分发 | 在一个节点构建并发布,其余节点导入 |
| 转发 | 评测器在 `/eval/*`,接单层在 `/intake/*`;静态工作台在 `/ui/` |
| 鉴权 | 可选 bearer;所有服务只绑定 `127.0.0.1` |
| 多副本 | 任意一个副本处理任意请求(D31)。副本共享的只有注册表:路由(沙箱 → 节点)、用户、经 `POST /nodes` 登记的节点;每个副本自己轮询节点健康、自己记审计、自己记两次轮询之间的反馈。对账与 evacuate 取租约,一个节点同一时刻只有一个副本在做;租约到期自动放开。注册表不可达时副本不启动(没有注册表的副本会从空表路由)。实现是 Go(`cp/`),零依赖,RESP 客户端自带 |

## 租户与配额

账户(Account)⊃ 项目(Project)⊃ 成员(Member,带令牌),配额按项目(并发沙箱数、存储、当日花费,0 = 不限);部署者是所有账户的 admin,一个账户建好就带一个 default 项目。沙箱归项目:创建时按头、body 或查询串指定,不指定就是调用者账户的 default;成员只看到本账户的沙箱,别的账户的对他不存在。创建前按配额准入:沙箱数到上限 429,当日花费到上限 402。这些存 SQL(单副本 SQLite,多副本 Postgres),是沙箱侧唯一不能从节点重建的数据,连同下面的计量。

## 计量

每分钟一次 tick(多副本时一个副本做,租约):运行中的沙箱按 vcpu 秒、内存 MiB 秒计,运行或暂停的按可写层 MiB 秒计;模型用量从模型代理读累计值记增量,费用由代理定价。价目表版本化,改一次一个版本。项目的当日花费从这里读,配额里的 daily_usd 用它准入。账单按项目、按时间段汇总出行项与总额。

## 模型代理

OpenAI 兼容端点,沙箱经出口代理可达。每台沙箱一个令牌与预算,按价格表计量,响应头回成本与 token 数,超预算返回 402。后端 upstream(DeepSeek 等)或 mock(确定性脚本,CI 用)。上游密钥从只读挂载的文件读,不进环境变量。

## 两类沙箱

| 项 | persistent | ephemeral |
| --- | --- | --- |
| 创建者 | 工作台、接单层 | 评测器、fork |
| 暂停 | 支持,空闲超时自动 | 不支持,到时即销毁 |
| bundle | 每次暂停后发布 | 不发布 |
| 节点故障 | 在别的节点从最近 bundle 恢复,最多丢一次暂停以来的写入 | 由创建者重新调度一次运行 |
| 结束后 | 保留到删除或到期 | 立即清理;只留导出的产物、事件摘要、失败现场 |
| 配额 | 计沙箱数量与存储 | 计并发评测上限 |

ephemeral 的失败靠重跑解决,所以评测任务必须可重试、幂等。
