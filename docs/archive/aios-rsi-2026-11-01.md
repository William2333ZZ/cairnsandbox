# Cairn 自举式 RSI 方案(修订版)

取代 `architecture.md` v0.1 原第二部分。2026-10-30 起,分层系统、8 组件可变层、两个改进循环、运行时候选的总体设计在 `architecture.md` v0.2 第 3 到 6 节;本文保留内核/服务切分、三个角色、门槛与风险的细节。

## 0. 为什么修订

原方案把"被构建的 Cairn"和"builder agent 的 harness"分成两个对象。这个划分不成立:**Cairn 本身就是 agent 的 harness**。因此:

- RSI 的优化对象就是 Cairn 代码库本身(自指,self-referential),不是单独的提示词仓库。
- 这对应文献中的 Gödel Agent、SICA、Darwin Gödel Machine(自指代码修改一类),而不是只改提示词/技能/记忆的一类。
- 适应度不再是"agent 把 Cairn 模块写得多好",而是"**跑在候选 Cairn 上的 agent 完成任务的表现**"。

仍然成立的部分:三区权限、沙箱外评测器、冻结的监督者、预算控制。但**区域边界要从"Cairn 之外"改为"切在 Cairn 内部"**。

## 1. 微内核式切分:Cairn 内部分为不可变内核与可变服务

| 部分 | 内容 | RSI 权限 |
|---|---|---|
| **不可变内核(TCB)** | 系统调用 ABI;能力(capability)检查;预算计量与强制;追加式审计/事件日志;agent 隔离与检查点原语;与 Sandbox Daemon 的桥(副作用唯一出口);晋升/回滚接口(只接受外部评测器的指令) | 不可改,人写,冻结,重点测试 |
| **可变服务** | 调度策略;上下文管理(压缩、换入换出);记忆管理(检索、遗忘);工具管理(选择、编排、重试);规划与反思循环;提示与技能;模型路由 | RSI 可改 |

要点:
- 可变服务只能通过**版本化的 ABI** 与内核交互,所以换实现不会破坏上层。
- ABI 本身不允许自动修改;ABI 变更须人工评审。
- TCB 要尽量小,因为它是整个系统唯一的信任基础。
- **强制边界靠权限隔离,不靠代码约定**:沙箱内的 Cairn 内核以独立用户运行、代码只读,可变服务以非特权用户运行并只通过 unix socket 的 ABI 与内核交互;成本、网络、资源、审计这些安全上限由沙箱之外(模型 API 代理、宿主机网络规则、cgroup、只追加日志)强制。详见 `decisions.md` D4。

## 2. 三个角色

| 角色 | 运行位置 | 作用 |
|---|---|---|
| **晋升控制器与已知良好版本** | 沙箱之外的确定性服务(不含 LLM)+ 注册表里不可变的 stage 0 制品;详见 `decisions.md` D3 | 验证评测器签名与门槛,执行晋升、回滚、强制终止 |
| **元 agent(改进者)** | `dev` 沙箱,运行在当前已晋升的稳定版 Cairn 上 | 读取 Cairn 源码与运行轨迹,提出对"可变服务"的 diff |
| **候选实例** | `eval-N` 沙箱,运行改动后的 Cairn | 在其上运行任务 agent,产生适应度数据 |

元 agent 改的是候选源码,不是正在运行它的那一份。这样改进者不会在自己脚下动手术。

## 3. 循环

```
1. 从档案库选父代 Cairn 版本(得分 + 新颖度)
2. 元 agent 读取父代源码与轨迹,提出小改动(单轮编辑数量有上限并随轮次退火)
3. Critic:改动是否只针对具体任务或具体评测
4. 构建候选 Cairn,fork 出 eval 沙箱
5. Gate 1:契约测试(ABI、安全性质),必须 100% 通过,否则淘汰
6. Gate 2:系统性质测试(并发正确性、崩溃恢复、预算强制、越权被拒)
7. 适应度:在候选 Cairn 上运行任务 agent 的演化集,与父代比较(超过噪声才算提升)
8. 通过 → 跑留出集;不退步 → 入档案库
9. 涉及放宽权限、新增系统调用、修改服务边界 → 人工审批
10. 记录父子关系、diff、各项得分、成本、轨迹
```

## 4. 适应度与门槛

| 层 | 内容 | 作用 |
|---|---|---|
| Gate 1 | 契约测试、安全性质 | 通过/淘汰,不参与排序 |
| Gate 2 | 系统性质:并发、恢复、预算、权限 | 通过/淘汰 |
| 适应度 | 任务 agent 在候选 Cairn 上的成功率、token 成本、延迟、稳定性(方差) | 排序与晋升 |
| 回归 | 旧任务得分是否下降 | 晋升的否决条件 |

先估计噪声:同一版本每任务重复 K 次得到噪声带 δ;提升必须是同任务配对比较且超过 δ。

父代选择不用自身点分:文献(HGM)表明自身分数几乎不能预测后代质量(相关 0.29),子树后代成功率(clade 成功率)能(0.78)。因此档案库每节点维护 Beta 后验,父代按子树成功率的 Thompson 采样 × 1/(1 + 子代数) 抽取;任务成功向量与已有节点余弦 > 0.95 的候选需 critic 确认实质不同;稳定版终选用后验保守分位(5%)且评测次数 ≥ 5。

Critic 落到 diff 级:含任务名、答案、任务特定分支的编辑直接拒绝;触及评测、记录、传播相关代码的改动按篡改分类入账。每轮实验另跑一个匹配预算的"并行采样"基线,harness 提升必须也胜过它。各机制的出处与数字见 `rsi-algorithms-survey.md`。

## 5. 评测集划分:按任务领域切分

因为被优化的是通用 harness,所以按**任务领域**切分,检验改进是否泛化:

| 集合 | 例子 |
|---|---|
| 演化集 | 编码任务、命令行运维 |
| 留出集 | 文档与数据处理 |
| 隐藏集 | 长程任务、多 agent 协作、断线恢复场景 |

同时按改动类型(调度/上下文/记忆/工具)给每次改动打标签,统计哪类改动稳定带来提升。

## 6. 开放程度分级

| 级别 | 可改范围 | 条件 |
|---|---|---|
| R1 | 提示词、技能、记忆与上下文策略(配置/文本层) | 评测器与噪声估计就绪 |
| R2 | 可变服务的实现代码(上下文、记忆、工具、调度) | R1 稳定,Gate 1/2 完备 |
| R3 | 新增、拆分服务(架构变更) | 人工审批 |
| 永不 | TCB、ABI、评测器 | 人工评审,不在自动循环内 |

## 7. 防作弊:度量必须来自 Cairn 之外

候选 Cairn 能改调度、上下文、工具逻辑,就有可能少报成本、跳过检查、干扰计量。对策:

- **成本由外部测量**:token 用量来自控制面的模型 API 代理日志,资源用量来自节点的 cgroup 计量,不采信 Cairn 自报。
- **计量与审计在 TCB 内**,且日志写到沙箱外只追加的存储。
- **评测任务与隐藏测试在沙箱外**,候选 Cairn 不可见。
- 监测异常:读取非任务目录、修改测试或评测文件、访问 daemon socket、异常网络访问,作为"作弊指标"和得分一起记录。
- 晋升由外部评测器签名,TCB 只接受带签名的晋升指令。

## 8. 沙箱布局

| 沙箱 | 用途 |
|---|---|
| `dev` | 元 agent 的工作区:Cairn 源码、轨迹、档案库视图 |
| `eval-N` | 每个候选一个,运行候选 Cairn 与任务 agent,评完销毁 |
| `integration` | 系统性质测试、故障注入、压力测试 |
| 晋升控制器 | 沙箱之外的确定性服务,持有已知良好版本(不属于用户的任何沙箱) |
| 外部评测器 | 沙箱之外 |

## 9. 主要风险

| 风险 | 对策 |
|---|---|
| 候选 Cairn 篡改计量或评测 | 度量外部化;TCB 冻结;签名晋升 |
| 优化出只对某类任务有效的 harness | 领域切分的留出集与隐藏集 |
| 改动微妙地破坏并发或恢复 | Gate 2 系统性质测试;故障注入 |
| 自举时新版本管理自己出错 | 冻结的监督者;回滚 |
| 评测成本过高 | 小任务集、预算上限、缓存未变部分的结果 |
| 噪声当提升 | 重复运行估计方差 |
| 文献中没有直接可对照的"RSI 做 Cairn"的工作 | 这次检索没找到;不代表不存在,需要进一步调研;因此先走 R1 小步验证 |

## 10. 待决事项

1. TCB 的最小功能集与语言选择(倾向 Rust 或 Go,需端云都能运行)。
2. ABI 初稿由谁评审。
3. 首批任务 agent 的任务集(领域与验收脚本)。
4. 种子:从 DGM/SICA 开源种子 agent 派生,还是从零写 stage 0。
5. 人工审批的具体触发条件。
