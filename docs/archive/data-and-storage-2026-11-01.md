# 数据存储与缓存设计

沙箱里的 agent 会产生、读取、持久化各种数据,这些数据和用户一一对应,又要在暂停、fork、评测、本地与云端之间流动。本文档梳理问题、定义数据归属,并给出存储与缓存的设计。系统组成见 `architecture.md`,功能见 `feature-design.md`。

---

## 0. 问题清单

| # | 问题 | 为什么难 |
|---|---|---|
| 1 | 沙箱数据放在哪 | 本地盘快但节点坏了就丢;网络盘安全但慢且贵 |
| 2 | 数据归属与访问 | agent 在沙箱里跑,却要读写属于某个用户或项目的数据;不能给它直连存储的凭证 |
| 3 | 多租户隔离 | 共享缓存与共享存储可能泄露别人的数据,或被别人投毒 |
| 4 | 一致性 | 暂停、快照时文件系统可能写到一半;agent 检查点和文件快照必须成对一致 |
| 5 | 记忆的持久化 | 长期记忆跨沙箱存在;不可信内容被写进去会长期污染 agent |
| 6 | 删除与合规 | 删除用户要覆盖文件、快照、记忆、日志、缓存;审计日志又要求保留 |
| 7 | 评测可复现 | 缓存、记忆、依赖版本一旦漂移,候选之间就不可比 |
| 8 | 本地与云端 | 本地数据含用户真实文件,同步到云端有隐私问题;两边还要处理冲突 |
| 9 | 体量与成本 | 快照、fork、事件日志会快速膨胀 |
| 10 | 故障恢复 | 节点故障时能恢复多少,丢多少 |

## 1. 数据范围与归属

引入一个新的归属单位:**项目**。

| 范围 | 含义 | 例子 |
|---|---|---|
| 用户 | 账号级 | 偏好、模型密钥、全局设置 |
| 项目 | 一组相关沙箱共享的数据域 | 长期记忆、产物、任务集、实验 |
| 沙箱 | 单个环境 | 文件系统、会话记忆、进程 |
| 任务 | 单次目标 | 上下文、检查点、事件 |

规则:
- 每个沙箱属于**一个项目**;默认每个用户有一个默认项目,暂不做团队共享。
- 沙箱之间共享数据只能经过**项目级**的存储(产物库、长期记忆),并通过显式操作。
- 沙箱启动时获得一个**范围令牌**,声明用户、项目、沙箱、任务标识。沙箱内所有对平台存储的访问都带这个令牌,由控制面的服务校验,**不在沙箱内放对象存储或数据库的凭证**。

## 2. 数据清单

| 数据 | 范围 | 存放 | 生命周期 | 敏感度 |
|---|---|---|---|---|
| 账号、沙箱、任务、实验、版本元数据 | 用户/项目 | PostgreSQL | 随对象 | 中 |
| 事件(轨迹) | 任务 | 近期在数据库或流,冷数据压缩后进对象存储 | 按保留期 | 高(含命令与文件内容) |
| 审计日志 | 用户/平台 | 独立的只追加存储;哈希链按沙箱或分片切分,定期汇总锚点 | 长于其他数据 | 高 |
| 沙箱文件系统 | 沙箱 | 节点本地可写层 + 对象存储中的增量快照 | 随沙箱,暂停后保留 | 高 |
| 模板与镜像层 | 平台 | 对象存储,内容寻址;节点缓存 | 版本化 | 低 |
| agent 检查点 | 任务 | 对象存储(内容寻址 blob),元数据在数据库 | 随任务,保留期 | 高 |
| 会话记忆 | 沙箱 | 沙箱内文件,随文件系统快照 | 随沙箱 | 高 |
| 长期记忆 | 项目 | 记忆服务(数据库 + 向量索引) | 用户可控 | 高 |
| 产物与用户上传 | 项目 | 对象存储,按用户前缀,版本化,加密 | 用户可控 | 高 |
| 密钥与凭证 | 用户 | 密钥管理服务 | 用户可控 | 极高 |
| 任务集与隐藏测试 | 项目 | 评测器专属存储 | 随任务集 | 高 |
| 评测结果与签名 | 实验 | 评测器专属存储 | 随实验 | 中 |
| CairnSandbox 版本制品 | 项目 | 注册表,内容寻址 | 版本树管理 | 中 |

## 3. 存储分层与数据流

### 3.1 四类存储

| 层 | 内容 | 特点 |
|---|---|---|
| 控制面数据库 | 元数据、权限、版本树、事件索引 | 强一致,体量小 |
| 对象存储(S3 兼容) | 快照、检查点、冷事件、产物、任务集、镜像层 | 便宜、持久、慢;内容寻址去重 |
| 节点本地盘 | 沙箱可写层、镜像层缓存、包缓存 | 快、易失,可重建 |
| 专用存储 | 审计日志、评测器数据、记忆索引 | 独立凭证,独立访问路径 |

### 3.2 沙箱磁盘模型

- 根文件系统 = **只读基础层**(模板,节点缓存,多沙箱共享)+ **每沙箱一层本地可写层**。
- 可写层在节点本地盘,写入快。
- **持久型沙箱**运行期间,守护进程把可写层的**增量定期同步到对象存储**(默认每 5 分钟,数值为初值),暂停时再同步一次。临时型沙箱不做定期同步,见 3.5。
- 因此沙箱与具体节点**解耦**:节点故障时,在别的节点用基础层加最近一次增量即可恢复,最多丢失一个同步周期内的写入(恢复点目标约 5 分钟)。

这吸收了 DSec 的经验:写入留在本地,只读数据按需从共享存储读取。

### 3.3 暂停、快照、恢复的一致性

```
暂停/快照:
1. 守护进程通知 agent 到达步边界,创建检查点
2. 文件系统静默(刷盘并冻结写入)
3. 生成可写层增量并上传,得到清单(内容哈希列表)
4. 清单与检查点成对记录到数据库,标记为一致点
5. 解冻(快照)或停止进程(暂停)

恢复:
1. 在任意节点拉取基础层(命中缓存则跳过)
2. 按清单惰性加载增量
3. CairnSandbox 从配对的检查点恢复上下文
```

- 检查点与文件快照**必须成对**才算有效恢复点。只有一半的不可作为恢复点。
- 如果静默失败(例如有进程持续写入),快照标记为"崩溃一致",界面提示。

### 3.4 fork

- fork = 以某个快照的清单为起点,新建沙箱的可写层(写时复制,不复制数据)。
- 因此 fork 很便宜,实验里大量 fork 评测沙箱不会成倍占用存储。

### 3.5 沙箱类型:持久型与临时型

两类沙箱对存储的要求差别很大,必须分开处理,否则评测沙箱会白白产生大量同步与存储流量。

| 项 | 持久型 | 临时型 |
|---|---|---|
| 创建者 | 用户在工作台创建 | 实验自动创建(评测、重复运行);用户也可显式创建"一次性"沙箱 |
| 定期增量同步 | 是(默认 5 分钟) | **否** |
| 暂停 | 支持,保留文件 | 不支持,到时即销毁 |
| 快照与 fork | 支持 | 默认不做;fork 评测沙箱时用写时复制,不额外占存储 |
| 节点故障 | 在别的节点恢复,最多丢一个同步周期 | 由评测器重新调度该次运行,不尝试恢复 |
| 结束后 | 保留到删除或到期 | 立即清理可写层;只保留最终产物导出、事件摘要和失败现场(短保留期) |
| 配额 | 计入沙箱数量与存储配额 | 计入"并发评测沙箱上限",不占沙箱数量配额 |
| 事件保留 | 按项目保留期 | 短保留期,失败的运行保留更久用于分析 |

临时型沙箱的失败可以通过重跑解决,这是它能省掉持久化成本的前提;因此评测任务本身必须可重试、幂等。

## 4. 记忆与用户数据

### 4.1 作用域与访问路径

| 记忆 | 作用域 | 访问路径 |
|---|---|---|
| 会话记忆 | 沙箱 | 沙箱内文件,直接读写 |
| 长期记忆 | 项目(可选限定到沙箱) | **只能通过记忆服务的接口**,凭范围令牌,不直接读存储 |

长期记忆放在沙箱之外,原因:沙箱会被删除或 fork,记忆不应随之消失;也便于做审计、检索、用户管理。

### 4.2 防污染

记忆会让一次注入影响之后很多次任务。措施:
- 每条记忆带**来源**(用户输入、agent 推断、工具输出、网页)和时间。
- 来自不可信来源(网页、第三方文档、工具输出)的条目标记低信任,**作为资料而不是指令**注入上下文。
- 写入有速率和大小上限。
- 用户可以查看、编辑、删除、导出全部记忆;敏感条目需用户确认才写入。
- 过期与遗忘:未被使用的条目按策略衰减。

### 4.3 用户数据

- 用户上传的文件和产物进入**项目产物库**(对象存储),沙箱拿到的是副本(只读挂载或拷贝)。
- 沙箱里的修改不会自动回写产物库;需要显式导出,并生成新版本。
- 沙箱不应成为任何数据的**唯一副本**:重要结果经导出进入产物库。

## 5. 缓存

| 缓存 | 位置 | 键 | 隔离 | 失效 | 评测中 |
|---|---|---|---|---|---|
| 镜像层 | 节点本地 | 内容哈希 | 共享只读 | 哈希变化即新对象 | 可用 |
| 依赖包(pip、npm、go、apt) | 平台内的读穿代理 | 包名+版本+哈希 | 公共包共享;**私有包不共享缓存** | 依据锁文件与固定快照 | 可用,**须固定到同一份镜像快照** |
| 模型调用的提示缓存 | 模型服务端 | 稳定前缀 | 按账号 | 服务端控制 | 可用(不改变输出分布) |
| 模型响应缓存(整体复用回答) | — | — | — | — | **评测中禁用**,否则掩盖方差 |
| 嵌入与检索索引 | 记忆服务 | 内容哈希 | 按项目 | 内容变化重建 | 评测沙箱使用空或固定索引 |
| 评测结果 | 评测器存储 | CairnSandbox 版本哈希+任务集版本+模型版本+种子 | 按实验 | 任一要素变化即失效 | 即其本身 |
| 候选构建 | 节点或构建服务 | 源码哈希 | 按项目 | 源码变化 | 可用 |
| 会话路由、状态 | 内存缓存 | 沙箱标识 | 内部 | TTL | — |

规则:
1. **沙箱对共享缓存只读**。只有代理和构建服务能写入,并校验哈希或锁文件,防止被沙箱内代码投毒。
2. 含用户私有信息的缓存**键带用户或项目前缀**,不跨租户命中。避免通过命中与否推断别人的依赖(侧信道)。
3. 缓存不可成为正确性的依赖:丢了只会变慢。
4. 评测用到的所有缓存必须**可固定、可记录**,记入实验的可复现信息。

## 6. 隔离、加密与删除

### 6.1 访问路径

```
沙箱内代码
   │  范围令牌
   ▼
控制面服务(文件同步、记忆、产物、审计写入)
   │  校验用户/项目/沙箱
   ▼
存储(对象存储、数据库、记忆索引)
```

- 对象存储访问通过控制面签发的、限定前缀和时效的预签名地址。
- 沙箱无法列出或读取其他沙箱、其他用户的前缀。
- 审计日志的写入口只对守护进程开放,沙箱内读写均不可。

### 6.2 加密

- 传输加密。
- 静态加密采用**信封加密**:每个用户一把数据密钥,由主密钥保护。

### 6.3 删除语义

| 对象 | 删除行为 |
|---|---|
| 沙箱 | 删除可写层、快照、会话记忆;事件按保留期清理 |
| 项目 | 删除产物库、长期记忆、任务集、实验数据 |
| 用户 | 销毁该用户的数据密钥("加密粉碎"),使所有备份、快照中的该用户数据同时不可读;再异步清理实际对象 |
| 审计日志 | 保留期内不删除;内容中的敏感载荷做脱敏或只存摘要,以减少与删除要求的冲突 |

## 7. 本地站点的数据

| 项 | 规则 |
|---|---|
| 存放 | 本地沙箱的可写层、会话记忆、事件、检查点都放在桌面端的本地数据目录 |
| 默认不上云 | 本地文件内容和包含内容的轨迹**默认不同步到云端** |
| 同步内容 | 默认只同步元数据到审计:动作类型、时间、路径摘要、大小、成本;内容需要用户显式选择 |
| 与云端交换 | 通过显式的"导出到云端/下载到本地",走产物库 |
| 冲突 | 本地叠加层的修改只通过差异审阅应用到真实文件,不做双向自动同步,因此不存在静默覆盖 |
| 加密 | 本地数据目录静态加密,密钥保存在系统钥匙串 |

## 8. 评测与自我改进的数据

- 实验只使用**任务集中的数据**,不接触用户的私有文件,除非用户把它们显式放进任务集。
- 评测沙箱:空记忆或固定记忆快照、固定依赖快照、固定模型版本、网络受限,保证候选之间可比。
- 评测器数据(验收脚本、隐藏测试、答案)在评测器专属存储中,沙箱网络不可达。
- **经验档案**(保存的原始轨迹,供元 agent 分析)可能包含任务数据与模型输出:按项目隔离,设保留期,不跨项目使用。
- CairnSandbox 版本制品内容寻址存储;版本树的元数据在数据库。

## 9. 容量、保留与回收

| 项 | 规则 |
|---|---|
| 磁盘配额 | 节点用文件系统配额限制每个沙箱可写层大小,接近上限时提示,写满时只阻止写入 |
| 快照 | 数量与总量受项目配额限制;增量与内容寻址去重 |
| 事件 | 近期保存在热存储;超期压缩转冷;大输出落盘为对象,事件里只留引用 |
| 保留期(初值) | 暂停的沙箱 7 天;事件热存储 14 天,冷存储 90 天;审计日志 1 年;被淘汰的候选在实验结束后 30 天清理 |
| 临时型沙箱 | 结束后立即清理可写层;成功的运行只保留事件摘要与最终产物,失败的运行保留现场 7 天 |
| 回收 | 定期扫描无引用的对象(孤儿快照、被删除 fork 的残留、过期缓存);删除前先标记再延迟清理 |
| 分层 | 长期未访问的快照迁移到更便宜的存储层 |

数值均为初值,需根据实际用量调整。

## 10. 故障与恢复

| 情形 | 行为 |
|---|---|
| 节点故障 | 在其他节点用基础层加最近增量恢复;最多丢失一个同步周期的写入 |
| 对象存储暂时不可用 | 沙箱继续运行,同步排队重试;超过阈值提示用户风险 |
| 数据库不可用 | 运行中的沙箱不受影响;新建、暂停、晋升等控制面操作失败并提示 |
| 快照上传中断 | 清单未提交则不生效,旧恢复点保持有效 |
| 记忆服务不可用 | 任务可继续,长期记忆暂不可用并在事件里标注 |
| 审计存储不可用 | 沙箱内高风险动作暂停,宁可停也不丢审计 |

## 11. 关键决策

| 编号 | 决策 | 理由 |
|---|---|---|
| S1 | 引入"项目"作为数据范围 | 记忆与产物需要跨沙箱共享,又要隔离于其他项目 |
| S2 | 沙箱与节点解耦:可写层本地,增量定期同步到对象存储 | 兼顾速度与持久性,节点故障可恢复 |
| S3 | 沙箱内不放存储凭证,一切经范围令牌与控制面服务 | 降低被攻破后的泄露面 |
| S4 | 长期记忆放在沙箱之外,经记忆服务访问 | 不随沙箱消失,便于审计与用户管理 |
| S5 | 共享缓存对沙箱只读,键带租户前缀,私有内容不跨租户命中 | 防投毒与侧信道 |
| S6 | 评测禁用整体响应缓存,依赖与记忆固定 | 保证可复现与方差可测 |
| S7 | 用户级数据密钥,删除用户时加密粉碎 | 覆盖备份与快照中的数据 |
| S8 | 本地内容默认不上云,只同步元数据 | 本地含用户真实文件,隐私优先 |
| S9 | 沙箱分持久型与临时型,临时型不做定期同步与长期保留 | 评测沙箱量大且可重试,持久化是纯成本 |
| S10 | 运行态以节点为准,数据库只记生命周期转换 | 避免每个沙箱的状态变化都打数据库,控制面可水平扩展 |
| S11 | 事件与审计走批量流水线,序号和哈希链按沙箱或分片切分 | 避免全局串行与热点 |

## 12. 待决事项

1. 对象存储与密钥管理用自建还是云服务。
2. 增量同步的具体实现(文件级差异、块级差异或内容定义分块)与同步间隔。
3. 长期记忆的检索方式(关键词、语义,还是两者)与向量索引选型。
4. 审计日志与"被遗忘权"的具体平衡(哪些字段脱敏、保留多久)。
5. 事件的保留期与是否允许用户自助导出全部轨迹。
