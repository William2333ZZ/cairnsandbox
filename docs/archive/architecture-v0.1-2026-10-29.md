# 云端沙箱管理系统 + RSI + Cairn 开发架构

版本:v0.1(设计草案)
范围:第一部分是平台架构,第二部分是在沙箱内用 RSI(递归自我改进)开发 Cairn 的方法。

---

## 0. 一页摘要

- 要做的是一个**云端沙箱管理系统**:一个用户可以拥有多个沙箱,每个沙箱里有执行环境和 agent。
- 在此之上做 **RSI**:Cairn 就是 agent 的 harness,RSI 改进的是 Cairn 的可变服务层(调度、上下文、记忆、工具、提示与技能),由**沙箱外的评测器**判定好坏。
- 客户端有 **Web 端**和**桌面端**,桌面端可以在本地运行同一套 agent 运行时(本地站点)。
- 用这套系统去开发 **Cairn**(面向 agent 的操作系统内核/运行时)。Cairn 同时是后续"端云统一内核"的基础。
- 刻意保持最小:加固的 Docker 隔离、文件系统级 fork;沙箱与节点解耦(可写层增量定期同步到对象存储)。microVM 与内存快照后置。

核心设计原则:

1. **三区分离**:固定基础设施与 Cairn 不可变内核(agent 不可写)、Cairn 可变服务(agent 可写)、外部评测器(agent 看不见)。
2. **接口先行**:沙箱协议、事件格式、状态格式一次定好,后端(Docker、Firecracker、本地进程)可替换。
3. **评测可信优先于功能丰富**:没有可信评测,RSI 没有意义。
4. **能不自研就不自研**:不写 VMM、不写 OS 内核、不写分布式存储。
5. **为规模预留接缝**:入口无状态、运行态以节点为准、沙箱分持久型与临时型。目标是几百到几千并发,更大规模的能力后置(见第 9 节)。

## 2. 组件说明

### 2.1 客户端

| 端 | 能力 | 说明 |
|---|---|---|
| Web 端 | 沙箱列表、终端、文件浏览、agent 对话与轨迹回放、RSI 面板 | 只连云端沙箱 |
| 桌面端 | 同 Web 端 + 本地 agent | Tauri 包装同一前端;本地 agent 是受限的本地进程,工作目录限定在用户选定文件夹,敏感操作需确认 |

两端使用同一套协议,沙箱属性中带 `site: cloud | local`。

### 2.2 控制面

- **Gateway**:认证(OAuth/API key)、把客户端 WebSocket 转发到对应沙箱 daemon、为沙箱签发**范围令牌**(声明用户、项目、沙箱、任务标识)。
- **Sandbox API**:生命周期管理,见第 4 节。**无状态**,可多实例部署。沙箱 ID 由随机部分和路由提示(创建时所在节点或分片)组成;沙箱的当前位置以路由存储为准,恢复到别的节点后更新路由,API 实例先用提示、查不到再查路由存储。
- **Scheduler**:先按健康与能力过滤节点,再随机采样几台取最空闲的;每个实例把自己刚做的、尚未反映到节点上报里的放置叠加到本地视图,不需要跨实例协调。**节点保留最终准入权**,容量不够就拒绝并重选。沙箱与节点解耦(见 `data-and-storage.md`),调度不依赖沙箱原来在哪台机器。对评测沙箱按项目的并发上限做节流排队,避免创建风暴。
- **Registry**:管理模板、快照清单、Cairn 版本(带 `parent_id` 的树形谱系)。
- **Accounts**:用户、项目、沙箱数量和资源配额。
- **Model Proxy**:沙箱调用模型的唯一出口;按沙箱令牌计量 token 与成本,执行预算上限;用户的模型密钥只在这里使用。
- **Memory Svc**:长期记忆服务,按项目隔离;沙箱只能凭范围令牌经接口读写;条目带来源与信任等级。
- **Artifact Svc**:项目产物库(版本化、加密),沙箱拿到的是副本,导出是显式操作。
- **RSI Service**:见第 6 节。
- **Audit Log**:所有 agent 动作(命令、文件修改、网络请求、模型调用)追加写入、哈希链;沙箱内无读写权限。

控制面是同一个 Go 代码库、同一个二进制,按模块组织,可多实例部署;不拆成多个独立服务。

**状态与一致性**:
- 运行中沙箱的状态**以所在节点为准**,节点定期上报汇总;数据库只记录生命周期转换(创建、暂停、恢复、失败、删除),不记录每次状态细节。
- 控制面有对账循环:发现数据库记录与节点上报不一致时,以节点为准修正,并处理孤儿资源。
- Scheduler、Watcher 不需要持久状态,重启后从节点上报重建。

### 2.3 节点

- **Node Agent**:接收控制面的创建/销毁/fork 指令,设置资源与网络限制,监控健康,上报心跳;运行期间把沙箱可写层的增量定期同步到对象存储。
- **节点缓存**:镜像层与依赖包缓存;对沙箱只读,只有代理和构建服务能写入并校验哈希。
- **镜像加载接口**:节点通过统一接口取得模板镜像,当前实现是整层拉取并缓存;接口允许以后替换为按需加载,而不改动上层。
- **隔离后端(可替换接口)**:
  - 首发:Docker,rootless、无特权、seccomp、只读 rootfs、默认断网、CPU/内存/PID/磁盘限额。
  - 后续:Firecracker microVM(需要 Linux + KVM),获得更强隔离和内存快照。

### 2.4 沙箱内部

| 部件 | 区域 | 职责 |
|---|---|---|
| Sandbox Daemon | A(只读) | exec、PTY、文件读写、事件上报、健康检查;协议见第 5 节 |
| Cairn 不可变内核 | A(只读) | ABI、能力检查、预算计量、审计、检查点原语、与 daemon 的桥 |
| Workspace | 任务相关 | 项目文件、依赖、任务输出;位于本地可写层,定期增量同步到对象存储 |
| Cairn 可变服务 | B(可写) | 调度、上下文、记忆、工具管理、提示与技能;RSI 的改动对象 |

Cairn 的不可变内核与 stage 0 由人编写。任务 agent 和起点实现可参考 DGM/SICA 开源种子 agent 或 Claude Agent SDK,通过事件协议接入,保证可替换。

## 4. 沙箱管理 API(概要)

| 操作 | 说明 |
|---|---|
| `POST /sandboxes` | 指定模板、资源、agent_version、网络策略 |
| `GET /sandboxes` | 列出当前用户的沙箱 |
| `POST /sandboxes/{id}/pause` `resume` | 暂停(检查点 + 文件增量同步后停止容器)/恢复(任意节点拉取基础层与增量) |
| `POST /sandboxes/{id}/fork` | 从当前文件系统状态或快照派生新沙箱 |
| `POST /sandboxes/{id}/snapshot` | 创建快照 |
| `DELETE /sandboxes/{id}` | 销毁 |
| `WS /sandboxes/{id}/stream` | 终端、文件事件、agent 事件的统一流 |
| `POST /sandboxes/{id}/tasks` | 提交任务给 agent |
| `POST /projects` `GET /projects` | 创建与列出项目 |
| `PUT /projects/{id}/artifacts/{path}` `GET` | 项目产物库的上传与下载(版本化) |
| `GET/PUT/DELETE /projects/{id}/memory/{item}` | 长期记忆的查看、编辑、删除(用户)与读写(沙箱经范围令牌) |
| `POST /projects/{id}/experiments` | 创建实验 |

幂等:创建和任务提交接受客户端提供的请求 ID。

## 5. 沙箱 Daemon 协议与事件格式

传输:云端 microVM 用 vsock,Docker 用 unix socket,本地用同一接口的本地进程通道。协议与传输无关。

### 5.1 请求

`exec`、`pty_open/pty_write/pty_resize`、`fs_read/fs_write/fs_list/fs_delete`、`health`、`agent_submit_task`、`agent_cancel`。

每个请求带 `request_id`。daemon 对已完成的 `request_id` 返回缓存结果,不重复执行(幂等)。

### 5.2 事件(追加式)

`message`(用户/agent 消息)、`tool_call`、`tool_result`、`command_output`、`file_changed`、`state_change`、`budget_update`、`error`。

所有事件带 `seq`(单调递增)、`timestamp`、`session_id`,支持断线重连后从某个 `seq` 继续。

### 5.3 约束

- 输出大小限制与截断(防止 `yes` 之类无限输出占满存储)。
- 命令超时与进程树清理。
- daemon 只监听 vsock/unix socket,不监听 TCP。

### 5.4 事件流水线

- 沙箱 daemon 把事件**批量**发出,每个沙箱有自己的序号,不依赖全局序号。
- 事件先进入流水线(队列),再分流:近期事件写入热存储以便回放,超期压缩转对象存储;大输出落为对象,事件里只留引用。
- 审计日志同样走流水线,但进入独立的只追加存储;哈希链按沙箱或分片切分,定期把各链的头汇总成一个锚点,避免全局串行。
- 写入失败时 daemon 本地缓冲并重试;缓冲满时对高风险动作暂停,宁可停也不丢审计。

## 6. RSI 服务

### 6.1 三区权限(安全基础)

| 区域 | 内容 | agent 权限 |
|---|---|---|
| A 固定基础设施 | daemon、Cairn 不可变内核(ABI、能力检查、预算计量、审计、检查点原语) | 只读 |
| B 可变 harness | Cairn 的可变服务层(上下文、记忆、工具、调度、提示与技能);详见 `aios-rsi.md` | 读写 |
| C 外部评测器 | 任务集、隐藏测试、打分、晋升决策 | 沙箱外,不可见 |

### 6.2 起步层级

Cairn 即 harness,RSI 的对象是 Cairn 的可变服务层。开放程度分级:R1 只改配置/文本层(提示词、技能、记忆与上下文策略),R2 开放服务实现代码,R3 允许架构变更(需人工审批);不可变内核、ABI、评测器永不在自动循环内。详见 `aios-rsi.md`。

### 6.3 循环

```
1. 从 AgentVersion 档案库按"得分 + 新颖度"选父代
2. 候选 agent 读取自己的运行轨迹,提出小改动(单轮编辑数量有上限,随轮次退火)
3. Critic 过滤:改动是否只针对具体任务
4. fork 沙箱,应用改动,运行"演化集"
5. 优于父代 → 运行"留出集";两集都不退步 → 入档案库,标记为候选版本
6. 涉及新增工具、放宽网络、访问用户数据 → 进入人工审批
7. 记录:父子关系、diff、分数、成本、轨迹
```

### 6.4 评测集

- **演化集**:用于选择。
- **留出集**:用于晋升,不参与提议。
- **隐藏集**:仅在阶段性评估时查看,不参与任何自动决策。
- 评测前先测噪声:同一版本重复运行,得到方差;提升必须超过噪声阈值。
- 晋升同时检查旧任务,防止能力退化。

### 6.5 预算与限制

单候选、单轮、总计三级 token/时间/CPU 预算;超限自动终止并记录。

### 6.6 防作弊

- 评测器与打分逻辑在沙箱外。
- 监测异常行为:读取非任务目录、修改测试文件、尝试访问 daemon socket、异常网络访问。
- 把"作弊指标"作为一等度量,与得分一起记录。

## 7. 安全模型

| 威胁 | 对策 |
|---|---|
| 沙箱逃逸 | 首发加固 Docker;面向不可信用户前必须升级 microVM |
| agent 篡改基础设施 | 区域 A 只读;AppArmor/文件权限限制 daemon 的 socket 与日志 |
| 窃取答案/评测 | 评测在沙箱外;隐藏集 |
| 无限输出、资源耗尽 | 输出截断、cgroup 限额、超时 |
| 网络滥用 | 默认断网,按任务白名单;出口审计 |
| 凭证泄露 | 沙箱内不放长期凭证;模型 API 通过控制面代理 |
| 提示注入 | 外部内容视为不可信数据;高风险动作确认 |
| 自我修改带来的权限升级 | 新增工具/放宽网络/读用户数据需要人工审批 |

第一版只面向内部或受控用户。

## 8. 技术选型

| 部分 | 选择 |
|---|---|
| 控制面 | Go + PostgreSQL |
| Daemon | Go 静态二进制(性能敏感时再评估 Rust) |

| Cairn 可变服务 / 任务 agent | 取决于种子实现(Python 或 TypeScript),在事件协议之后 |

## 9. 规模目标与预留

**目标**(粗估,尚未实测):同时存在几百到几千个沙箱,创建速度每秒几个到几十个,一次实验约一千个评测沙箱的突发,节点数十台。

**现在就做的接缝**:
- API 层无状态,沙箱 ID 带路由提示,位置以路由存储为准;
- 运行态以节点为准,数据库只记生命周期转换;
- 沙箱分持久型与临时型(见 `data-and-storage.md`),临时型不做定期同步与长期保留;
- 事件与审计走批量流水线,序号和哈希链按沙箱或分片切分;
- 镜像加载走统一接口;
- 调度采样加节点本地准入,评测沙箱按项目并发上限节流。

**为更大规模预留、暂不实现**:按需镜像加载、内存超卖与回收、CPU 分级调度、轻量函数后端、云上突发扩容。这些在需要承载更大并发(例如训练用的 rollout)时再做,当前不承诺。
