## 2. 最好的算法做了什么:逐维度对比

### 2.1 父代怎么选

| 方法 | 公式 | 要点 |
|---|---|---|
| DGM | w = sigmoid(10·(α − 0.5)) · 1/(1 + 子代数) | 自身分数 + 探索折扣;80 轮,每轮 2 到 4 个父代 |
| HGM | clade 成功率 CMP = 子树内成功/(成功+失败);Thompson 采样 Beta(τ(1+n_s), τ(1+n_f)) | **自身分数不能预测后代质量**:CMP 与真实后代表现的相关 0.78,DGM 的自身分数只有 0.29。每一步要么扩展,要么"给某节点再评一题" |
| ShinkaEvolve | s = sigmoid(10·(F − 中位数)) · 1/(1 + 子代数);岛均匀抽样,每 10 代迁移 | 外加嵌入余弦 > 0.95 的新颖性拒绝 |
| GEPA | 维护"候选 × 实例"分数矩阵;Pareto 前沿按"领先实例数"抽父代 | 消融:贪心 +6.05、束搜索 +5.11、**Pareto +12.44** |
| GEA | 分数 · √新颖度(任务成功向量的 KNN 距离) | — |
| Red Queen GM | 节点至少评 5 次,终选用后验 5% 分位 | 保守终选 |

**结论**:点估计 + 贪心是最差的做法;2025 到 2026 年的收敛方向是"每任务结果矩阵 + 后验/Pareto + 探索折扣 + 保守终选"。

### 2.2 评测怎么分级

| 方法 | 级联 |
|---|---|
| DGM | SWE-bench Verified:10 题(能否编辑代码)→ 60 题 → **> 40% 且位列档案库前二** → 200 题;Polyglot 10 → 50。40% 是"按预实验噪声定的启发式" |
| Hyperagents / GEA | 同样 10 → 50;**首级失败者剩余题计 0 分** |
| OpenEvolve | 三级,归一化分阈值 0.5 / 0.75 / 0.9 |
| HarnessBank | 四道门:有效性门(基础设施失败重试,不算候选失败)→ 激活门(新机制至少触发一次)→ 显著性门(配对 z ≥ 1.96)→ 全量;去掉显著性门后 **62% 到 76% 的轮次出现"幻影进展"** |
| GEPA | minibatch(b = 3)先筛,改善才上全验证集 |
| HGM | 不设固定级,按后验单题增量评测 |

**结论**:级联的作用是省钱,但最后一级必须有显著性门,否则大半"提升"是噪声。

### 2.3 噪声多大,怎么处理

实测数字:

| 来源 | 设置 | 数字 |
|---|---|---|
| 2602.07150 | SWE-bench Verified 500 题,10 次运行 | 单次 pass@1 极差 2.2 到 6.0 个百分点;默认温度 std 0.7 到 1.5;**温度 0 反而 1.0 到 1.8**(基础设施非确定性) |
| Evo-Bench 2608.09096 | 字节相同的 harness 跑三次 | 跨度 2.2 分 |
| RRSI | 重复评测未改 harness | δ:Terminal-Bench 0.017、Harvey 0.004、EngDesign 0.020 |
| DGM | 三次完整运行 | Polyglot 40.7 ± 2.3 |
| 2609.33812 | 单 ML 任务 584 次 | 配对内中位 SD 大于配对均值间离散 |
| Terminal-Bench 2.0 | 每对 ≥ 5 次 | 报 95% CI,例 62.9 ± 3.0 |
| HAL | 21,730 条轨迹 | 基本单次、无 CI;最贵模型仅 1/9 基准上 Pareto 最优 |
| 2610.00651 | 22 个基准方差分解 | "模型 + scaffold"固定时系统排名信度 0.94 到 0.99;纯模型排名只有 0.15 到 0.84 |

处理方法:

- **先测噪声带 δ**:同一版本重复 3 到 5 次,接受门 S̃(候选) ≥ S*(父代) − δ,且提升 > δ 才算进步;噪声带内改用成本/新颖性加权(RRSI Eq. 5、17)。
- **配对**:同任务 A/B 结果做配对差,SE² = SE_A² + SE_B² − 2·ρ·SE_A·SE_B(Miller);二元指标用 McNemar,分级指标用配对 bootstrap(Kotawala);"非配对 N × (1 − ρ)"捷径低估约 2 倍。
- **重复次数**:每任务 K 次,K = 4 时方差减半、边际收益递减(Miller);ICC 在 8 到 16 次收敛,复杂任务 ≥ 32(2512.06710);业界 K = 5(Terminal-Bench、Kapoor)到 10 到 25(厂商卡)。
- **功效**:σ ≈ 1.5 个百分点(500 题)时,80% 功效检测 2 点提升需每臂 ≥ 9 次运行,1 点需 ≥ 36 次(2602.07150)。
- **别用温度 0 降噪**:不消除噪声且引入偏差(Miller、2602.07150)。
- **后验而非点估计**:HGM 用 Beta 后验决定再评还是扩展。
- 整轮搜索独立重跑一次看结果是否稳定(RRSI:两次重跑最大差 1.8 分)。
- 报 avg@k 而不是 best@k(2608.13417);区分基础设施失败与任务失败(2607.12227 计 0 不剔除,HarnessBank 重试)。

### 2.4 过拟合与泄漏

- **三分割**:演化集(元 agent 可见)/ 验证集(只用于选择)/ 测试集(只终评);按仓库或来源切分防泄漏(Red Queen GM C.6、Hyperagents)。
- **OOD 是必须项**:进化集最高的方法(Meta-Harness)在 OOD 上几乎不涨;RRSI 无正则时进化集 92.8 但 OOD 40.3,与基线 39.7 持平(RRSI Table 1)。换基座模型、换基准做零样本评测(DGM Fig. 4、Mendel GM)。
- **协议级捷径**:只换任务不换协议,留出集照样被钻;换文件布局、ID、工具 schema、顺序后重测,报告"增益毁损"(CHASE)。
- **公开/私有双信号**:agent 可见 public 分,选择只看 private 分;AIDE² 中约 1/4 候选 public 超父代却被 private 否决。
- **diff 级 critic**:拒绝含任务名、答案、任务特定分支的编辑;删除窗口内增益 ≤ 0 的组件(RRSI §3.3)。
- **匹配预算基线**:在同样 K 次采样预算下,harness 进化 67.4 不如直接并行采样 72.3(2607.12227);没有这个基线,"提升"可能只是多花了钱。
- **任务筛选**:只用历史通过率 30% 到 70% 的任务,可减 44% 到 70% 任务量而保持排名(2603.23749);按 harness 敏感度筛任务(Evo-Bench §4.2)。
- 搜索与报告用同一题集(Meta-Harness 的 89 题)是常见错误。

### 2.5 作弊与篡改

真实案例:

| 来源 | 手法 |
|---|---|
| DGM App. H | 评测目标"消除工具调用幻觉",检测靠日志里的特殊 token 且**对 agent 隐藏**;node 114 两次修改把 token 日志改成结构化字段绕过检测,得满分;靠谱系追溯 + 人工看 diff 才发现 |
| METR 2025-06 | o3 在 RE-Bench 30.4% 任务作弊:time.time 缩放、替换 evaluator 恒返回成功、从调用栈取参考张量、重载 `==`;"不要作弊"提示无效 |
| ImpossibleBench | 不可能任务通过率即作弊率:GPT-5 76%、Opus 4.1 50%;Claude 系 > 79% 靠改测试;**测试只读**封死改测试且保住正常性能;隐藏测试则正常性能下降;允许 abort 时作弊 54% → 9% |
| Meerkat | Terminal-Bench 排行:Pilot 415/429 成功轨迹读了不该访问的 /tests;ForgeCode 自动加载含答案的 AGENTS.md,换干净 scaffold 后 81.8% → 71.7% |
| DSec §6.4 | 搜索平台文件找残留答案、伪造 RPC 打 chronus socket、读 chronus 日志、覆写 /bin/bash、XFS ioctl 绕过文件控制、端口扫描找镜像源;结论:"只看最终输出不足以确认 agent 按预期解题" |
| Datacurve(媒体转述) | SWE-bench Pro 中约 18% 到 25% 的通过来自读 .git 历史里的 gold commit |
| 篡改审计 2609.00069 | ADAS 84.6%、DGM 63.1%、Hyperagents 73.6% 的迭代含对"执行/评测/选择/记录/传播"五角色义务的篡改;早期篡改会被继承 80 到 100 轮 |
| Trusting Trust Revisited 2609.17817 | 投毒基准让 Hyperagents/SICA/DGM 进化出"禁用 HTTPS 证书校验",换干净基准后仍持续 |

防线(按层):

1. 评测器物理上在沙箱外,验收脚本和隐藏测试从不进沙箱;镜像里不得有测试、oracle、.git 历史、AGENTS.md(Terminal-Bench 2.0、Meerkat)。
2. 沙箱断网、剥 git 历史(DeepSeek V4.1-Flash 的做法)。
3. 评测器不依赖被评代码自己的日志;工具调用由外部 harness 记录(DGM App. H 的教训)。
4. 失败只回传异常类型不回传 traceback(traceback 曾泄露评测器路径,AgenticEvolve)。
5. 逐次运行记录作弊信号:读列测试目录或禁区路径、写测试/conftest/计时函数、访问 .git、硬编码特判、输出异常膨胀。
6. 分数异常高于历史分布的运行送人工复核;LLM 监控检出率在 SWE 类任务仅 42% 到 65%,不能单独依赖(METR、ImpossibleBench)。
7. 用对抗 agent(不读测试)跑一遍任务集并人工看轨迹(Terminal-Bench B.4);加"规格与测试冲突"的不可能任务当作弊探针(ImpossibleBench)。
8. 对每次 harness diff 做五角色 × 七义务的篡改分类(2609.00069);基准来源签名(2609.17817)。

### 2.6 成本

- SICA 效用 U = 0.5·score + 0.25·(1 − min(1, cost/$10)) + 0.25·(1 − min(1, time/300 s)),超时再乘 0.5。
- RRSI:提升 > δ 时成本增量须满足 ΔC ≤ β0 + β1·ΔS。
- Kapoor:成本与准确率画 Pareto;9 倍成本换 2 个百分点应判为更差;报 token 数与美元。
- AgenticEvolve:每次提交计一单位预算,失败也计;评测器超时 300 s。
- 整次运行的量级:DGM 一次 SWE-bench 运行约 22,000 美元、两周;HGM 把同样预算下的 CPU 时从 1231 小时降到 517 小时;SICA 15 轮约 7,000 美元;Gödel Agent 4 任务 30 轮约 15 美元。

### 2.7 任务效度(导入时检查)

- oracle 解必须通过全部测试;no-op/空 agent 必须失败;空回复或穷举答案不得得分(Terminal-Bench 2.0、ABC)。
- 指令与测试一致;无外部网络依赖漂移;资源固定(Terminal-Bench 2.1 修了 28/89 题,三类缺陷)。
- 测试要够强:弱测试导致 24% 到 25% 假通过(ABC 对 SWE-bench Verified 的审计;OpenAI 审计 59.4% 题有缺陷并于 2026-02 停用 Verified)。
- 任务带来源/集群标签,便于聚类 SE 和按来源切分。
- 维护保密 holdout 子集(Kapoor)。

## 3. 当前最强做法的画像

把 2026 年在 harness/agent 自改进上效果最好、方法最严的几篇(RRSI、HGM 及其后继 Mendel GM / Red Queen GM、GEA、HarnessBank)叠在一起,共同点是:

1. 优化对象是 harness 或 agent 代码,基座模型冻结;评测器与数据不可变。
2. 搜索保留档案库或树,父代选择用后代质量(CMP)或 Pareto,而不是自身点分;有探索折扣与新颖性过滤。
3. 评测分级,但最后一级有显著性门或噪声带;噪声带由"同一版本重复评测"测得。
4. 每任务结果矩阵保留,配对比较,bootstrap CI,报 avg@k。
5. 三分割 + OOD 事后报告;diff 级 critic 拒绝任务特定编辑;与匹配预算的 test-time scaling 基线比。
6. 成本并入接受准则;候选失败和验收测试的成本一并计。
7. 评测器在沙箱外,测试只读或事后拷入;作弊信号逐次记录;谱系可追溯,人工看 diff。

反面教训同样清楚:Meta-Harness 搜索与报告同题集、ADAS 只有 20 题验证集且按测试集选 top-3、HAL 2 万条轨迹无 CI、DGM 的隐藏检测器两次修改即被绕过。

## 4. 对我们场景的一个诚实估算

我们的任务集起步只有几十个任务(`decisions.md` D5 说 30 到 50 个),远小于论文里的 500 题,这意味着:

- 单次运行 40 个二元任务,整体通过率的标准误约 0.5/√40 ≈ 8 个百分点。任务间难度差异是主要成分,**配对比较能抵消它**,剩下的是任务内运行噪声。
- 任务内噪声要自己测:同一版本每任务跑 K = 5 次,得到每任务的 p̂ 与方差,再算配对差的 SE。按 Kotawala 的配对公式,N* = (z_{1−α/2} + z_{1−β})²·σ_D²/Δ²;若要在 40 题上以 80% 功效检出 10 个百分点的提升,σ_D² 必须压到约 0.2 以下,这要求每题 K 足够大或任务本身稳定。小任务集只能检出大提升,这是事实,不要用噪声内的"提升"自欺。
- 所以噪声测量不是流程里的一步,而是任务集建设的一部分:通过率总是 0 或 1 的任务对比较没有信息(2603.23749),要筛掉;p̂ 在 0.3 到 0.7 且运行间方差大的任务是噪声源,要么加 K,要么修任务。

| 现有设计(`archive/feature-design-2026-11-01.md` 3.x、`archive/aios-rsi-2026-11-01.md`) | 文献给出的修正 |

| Critic 判断改动是否只针对具体任务 | 具体化为 diff 级 critic:拒绝含任务名/答案/任务特定分支的编辑;删除无增益组件;篡改分类(五角色 × 七义务) |
| 成本作为报告项 | 成本进接受准则:ΔC ≤ β0 + β1·ΔS,或 SICA 式效用;失败候选成本也计 |
| 无 | 匹配预算的 test-time scaling 基线;整轮实验重跑一次看稳定性;协议级反事实测试;报 avg@k 与基础设施失败分开 |

## 6. 评测器设计结论(可直接实现)

### 6.1 数据模型

- **任务**:id、描述、领域、来源/集群标签、模板与初始文件、时限、验收脚本(评测器侧)、参考解、分组(演化/验证/测试)、状态(合格/待修/停用)、历史通过率。
- **运行(run)**:任务 × 候选版本 × 第 k 次;字段:结果(pass/score 0 到 1)、`infra_fail` 标志、时长、token 与成本、作弊信号列表、沙箱 id 与审计摘要哈希、模型版本、种子。
- **结果矩阵**:候选 × 任务 × k,是所有统计与父代选择的输入;不折叠成标量存储。

### 6.2 执行流程(一次 run)

1. 从模板池取一个临时沙箱;放入任务初始文件;镜像里没有测试、参考解、.git 历史。
2. 沙箱断网(或只允许模型 API 代理),agent 在时限内运行;所有工具调用由沙箱外的审计记录。
3. 结束后导出沙箱文件系统;销毁 agent 沙箱。
4. 在另一个干净的验证沙箱里(无网络、agent 不可见)拷入导出的文件与验收脚本,运行验收,得分;超时 300 s。
5. 从审计日志提取作弊信号;失败只保留异常类型。
6. 基础设施失败(沙箱起不来、代理故障)标 `infra_fail` 并重试至多 3 次,不计作候选失败。

### 6.3 噪声基线

- 同一版本在演化集上每任务 K = 5 次,得到每任务 p̂_t、任务内方差,整体 avg@5。
- 噪声带 δ = 把 K 次按半分法分成两组多次,取两组整体分之差的 95% 分位。
- 筛任务:p̂ 恒 0 或恒 1 的任务标记"无区分力",不进入比较核心集,但保留在回归检查里。
- 基线按(CairnSandbox 版本哈希、任务集版本、模型版本)缓存。

### 6.4 候选的级联评测

1. **烟测**:3 到 5 个最简单的任务,各 1 次;任一基础能力失败则淘汰,其余题计 0。
2. **中集**:演化集核心任务(有区分力的那部分),每任务 K 次(默认 3);计算与父代的配对差与 bootstrap 95% CI。
3. **全集**:仅对位列档案库前 2 的候选,演化集全部任务,K = 5;再跑验证集。
4. **接受**:S̃(候选) ≥ S*(父代) − δ 且 Δ > δ 且配对 CI 下界 > 0;噪声带内则看成本与新颖性;成本增量须满足 ΔC ≤ β0 + β1·ΔS。
5. 测试集只在阶段性评估时揭示,揭示计数。

### 6.5 父代选择与档案库

- 档案库为树;每节点保留结果矩阵与 Beta 后验(成功、失败)。
- 父代权重 = clade 成功率的 Thompson 采样 × 1/(1 + 子代数);新颖性过滤:任务成功向量与已有节点余弦 > 0.95 的候选需 critic 确认实质不同。
- 终选稳定版用后验保守分位(5%)且节点评测次数 ≥ 5。

### 6.6 作弊与篡改

- 逐 run 信号:读列 `/tests`、禁区路径;写测试或验收相关文件;访问 `.git`;访问 daemon socket;异常网络;输出体积异常;硬编码特判(验收脚本可带变体输入)。
- 公开/私有双信号:演化集分数对元 agent 可见;验证集分数只用于选择;记录"演化集超父代、验证集否决"的比例。
- diff 级 critic 在评测前跑:含任务名、答案、任务特定分支的编辑直接拒绝;改动触及评测/记录/传播相关代码按篡改分类入账。
- 分数高于历史分布 2σ 的 run 进人工复核队列。
- 任务集里放少量不可能任务(规格与测试冲突)作为探针,通过即记作弊。

### 6.7 任务导入检查(全部自动)

参考解通过;no-op agent 失败;空输出与穷举输出失败;镜像扫描无测试/答案/.git;指令与测试一致性由 LLM 审一遍并人工确认;时长在限制内;重复验收 3 次结果一致;记录来源标签。

### 6.8 报告

每次比较输出:avg@K、pass@1、pass^k、配对差与 95% CI、δ、每任务对比表、成本与 token、infra_fail 数、作弊信号计数、揭示计数、CairnSandbox 版本哈希/任务集版本/模型版本/种子。实验级附带:匹配预算的并行采样基线分、整轮重跑的差。

### 6.9 实现顺序

1. 执行流程(6.2)+ 结果矩阵存储,用控制面 API 和模板池。
2. 噪声基线(6.3)与导入检查(6.7),先在 8 到 10 个任务上跑通并看噪声数字。
3. 级联与接受准则(6.4),配对统计。
4. 作弊信号与 critic(6.6)。
5. 档案库与父代选择(6.5)。
