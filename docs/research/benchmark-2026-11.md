## 怎么读这些数(2026-11-03)

跑法:`NODE_TOKEN=… python3 ops/bench.py http://127.0.0.1:18800 --n 5 --ramp 16 --mem 128`,直连节点(不经控制面;经控制面每次多 1–3 ms 转发)。开发机是共享的 192 核 / 1 TB 机器,节点容器限 MAX_VMS=32、8 GiB 预算;爬坡故意停在 16 台,不是触顶——这不是压力测试(见 [no-stress-tests]),是量级。

| | 我们(这台机器) | CubeSandbox 自报 | 说明 |
| --- | --- | --- | --- |
| 创建 | 冷启 **396 ms**;快照热启此前量过 **~80 ms**(本节点今天没有模板快照,没进表) | < 60 ms | 它的 60 ms 是"模板快照恢复 + TAP 预建 + 预分配"。我们热启同量级;要再降,是 TAP 池与预分配 upper 这两件事(D30 清单) |
| 第一次 exec / 之后每次 | 11 ms / **5 ms** | 没报 | vsock 往返,够用 |
| 暂停 / 恢复 | 148 / 113 ms | 没报 | Diff 快照 + 杀进程 / 新进程 + 加载;恢复里有合并链的开销(uffd 在 jail 下不可用) |
| 检查点 / 回滚 | **47 ms** / 238 ms | 没报(它有 rollback,没公布数) | 检查点运行中打,停顿几十毫秒;回滚 = 杀 + 换盘 + 恢复 |
| fork 一台 | 328 ms | 没报 | 含父快照、squash、两边恢复 |
| 每台内存开销 | 空闲 **~60–72 MiB**(cgroup 增量,128 MiB 的 guest) | < 5 MB | **口径不同**:它的 5 MB 大概是 VMM 自身开销,不含 guest 实际触碰的页;我们的数含 guest 已触碰页与页缓存。要可比,得量"VMM RSS 减 guest 驻留页"。pmem/DAX 基础镜像(此前量过省 71%)在这台节点没开(LAZY_STORE 路径) |
| 密度 | 16 台没触顶,爬坡中创建不变慢(p95 422 ms),exec 6 ms | 单机数千 | 这台限 32 台,没法量"数千";按 60 MiB/台算,1 TB 机器内存上限约一万台,实际瓶颈会先到 tap / cgroup / 文件句柄,要真机专用才能量 |

结论:**热启与检查点一档,冷启与 fork 慢在 300–400 ms 这一档(VMM 起进程 + 盘准备),每台内存要换口径再比,密度量不了。** 下一步按收益:①生产节点开模板快照与 pmem 基础镜像再量一遍;②TAP 预建池;③专用机器上爬到触顶。

- **热启 85 ms(p95 126 ms),第一次 exec 5 ms**:和 CubeSandbox 自报的 < 60 ms 同一量级,差的那 25 ms 大概就是它预建的 TAP 与预分配。模板快照建一次 1.2 s,之后每台都从它起。
- **pmem 没省内存**:每台 62 MiB 对 72 MiB;此前量过省 71% 是在本地 base 文件上,这台节点的 base 经 lazyfs(FUSE)挂载,DAX 的页缓存共享在 FUSE 之上不成立。要 pmem 的收益,base 得是本地文件(LAZY_STORE 关掉或把 base 预热成本地副本)。pmem 的热启 103 ms,略慢于普通 85 ms,同一原因。
- 其余数和第一次一致(冷启 393、检查点 48、回滚 265、fork 345、exec 6 ms),噪声在 10% 内。

更新后的结论:**热启 85 ms、检查点 48 ms 与它一档;冷启 / 回滚 / fork 在 250–400 ms 一档;每台内存 60–70 MiB 要换口径再比,pmem 在 lazy base 上无效。**
