## 1. 现在的控制台哪里不对

截图见 [README](../../README.md) 的那几张。逐条对照代码(`web/src/layout/Shell.tsx`、`plugins/cloud|sandboxes|nodes`)得到:

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | **沙箱云被埋在个人 agent 应用里**。侧栏 14 个入口,沙箱云只占 3 个(沙箱、控制台、节点),其余是对话、待处理、接单、agent、例行、记忆、接入、版本、评测、我的目录、设置 | 一个想只用沙箱的外部团队,打开就是"这是你的 agent"的对话页 |
| 2 | **没有"当前项目"的全局概念**。项目切换只在控制台页顶部,沙箱页、卷、节点页不跟随 | 沙箱列表按令牌可见范围列,不按所选项目 |
| 3 | **不分角色**。owner 点"节点"看到红字 `deployer only`;member 能看到"换令牌"按钮但点了才 403 | 没有按角色隐藏 |
| 4 | **没有时间维度**。没有任何一条曲线:CPU、内存、盘、出站、花费都是此刻的一个数 | 账单只有"今天"与"近 30 天"两个总数 |
| 5 | **列表只是列表**。没有搜索、过滤、排序、批量操作、列选择;只按 5 秒轮询刷新 | 沙箱页 `setInterval(load, 5000)`;控制面其实已有 SSE `/events/stream` |
| 6 | **详情页是一整页的堆叠**。状态、检查点、端口纵向堆,没有标签;终端 / 文件 / 事件流在右栏另开 | 出口决定日志(`GET /sandboxes/<id>/egress`)、事件、审计都已有接口,界面里**看不到** |
| 7 | **没有上手路径**。空状态只写"没有沙箱";没有"拿到密钥、装 SDK、建第一台"的引导 | 新租户不知道 URL 与令牌怎么用 |
| 8 | **没有密钥管理**。令牌就是成员令牌,一人一个、不能命名、不能限范围、不能分别撤销 | 对比 Daytona 的命名 + 过期 + 权限范围的密钥页 |
| 9 | **成本无法归因**。能看总数,看不到"是哪台沙箱、哪个标签花的" | 对比 Vercel 把指标直接对齐计费并按沙箱 / 会话分组 |
| 10 | **模板没有"就绪 / 健康"概念**。只有一张列表 | 对比 CubeSandbox 的模板健康检查与版本矩阵 |
| 11 | 只有中文 | 对标产品都是英文优先 |

## 2. 同类产品的控制台怎么组织

(来源在文末;E2B 与 Modal 的搜索只拿到二手描述,标注了。)

| 产品 | 值得学的 |
| --- | --- |
| **Vercel Sandbox** | 控制台里有 Observability:**按沙箱名或会话 id 分组**的 Active CPU(核·小时,等 I/O 不计费)、Provisioned Memory(GB·小时)、Data Transfer、运行中沙箱数;团队与项目两级;**指标的口径就是计费的口径**,所以能把成本归到具体负载;CLI 能查同样的数 |
| **Daytona** | 组织级多租户,沙箱 / 快照 / 卷都属于组织;**密钥页**:名字、过期时间、权限范围(沙箱 / 快照 / 卷 / 审计 / 账单各自读写删),**管理密钥**能派生子密钥,创建者**给不出自己没有的权限**(整个请求被拒,不是被裁剪);owner 能看全部密钥,其他人只看自己的;看账单要角色里有 `read:billing` |
| **E2B** | 团队级 API key;每沙箱的 CPU / 内存 / 磁盘指标**每 5 秒**一个样本,SDK 与 CLI 都能取(二手来源:社区仪表盘仓库描述有用量分析页) |
| **Modal** | 用量页按应用拆分、出站流量按应用拆分;**预算**按环境与工作区设上限;给应用打标签来把花费归到团队或项目;`modal dashboard` 从命令行直达(二手来源) |
| **CubeSandbox** | 概览(节点就绪、容量)→ 模板商店 / 模板(就绪状态)→ 沙箱(从模板建,详情页看实时日志);v0.4 起的版本矩阵与模板健康检查;节点运维拆到 CubeOps。**没有租户、密钥、配额、用量**(单租户运维视角) |

**共同点**:① 团队 / 组织 / 项目的切换在最上面,所有页面跟着它;② 用量与计费同口径、能下钻到单台沙箱;③ 密钥是一等公民;④ 先有"概览",再有对象列表,最后才是对象详情;⑤ 运维面与租户面分开。

## 3. 设计原则

1. **项目优先**:顶栏永远有当前项目,所有页面按它过滤;组织级的东西(成员、账单汇总、审计)放在项目之外的"组织"区。
2. **按角色长出界面**:member 看不到 owner 的按钮,owner 看不到 operator 的节点页;不是点了才 403。
3. **每个数字都能下钻**:概览上的"今天 $3.2" 点进去按沙箱、按标签拆;沙箱页的曲线点进去是它的事件与决定。
4. **默认是活的**:列表走 SSE,变了就动;详情的曲线 5 秒一个点。
5. **有后果的动作先给预览**:回滚会丢什么、排空会搬哪几台、放宽会放开哪些域名。
6. **开发者先行**:每个操作旁边有"等价的 SDK / curl"一键复制;空状态直接给能跑的代码,URL 与项目已填好。
7. **沙箱云独立成壳**:自己的外壳与导航;个人 agent 工作台是另一个应用,右上角应用切换器互通。

## 4. 信息架构

```
控制台(独立外壳)                                    应用切换器:[ 沙箱云控制台 | Agent 工作台 ]
├─ 项目切换(顶栏)  ·  组织名  ·  角色标记  ·  搜索 / 命令面板(⌘K)  ·  账号
├─ 概览                  今天的花费与预算、运行中沙箱、容量、待批的放宽、最近的事;空状态 = 上手引导
├─ 沙箱                  列表(搜索、过滤、批量)  →  详情(概览 | 指标 | 终端 | 文件 | 网络 | 检查点 | 端口与卷 | 事件)
├─ 模板与镜像            模板(就绪 / 构建中 / 失败、各节点分布矩阵)· 层 · 构建(含日志)
├─ 卷
├─ 网络                  项目默认策略 · 放宽审批队列 · 出口决定日志(按沙箱)· 凭证(operator)
├─ 用量与账单            曲线(小时 / 天)· 按沙箱 / 标签 / 类别拆分 · 预算与阈值 · 结算与 CSV
├─ 成员与密钥            成员(邀请、角色)· API 密钥(命名、过期、范围、撤销、最后使用)
├─ 审计                  按项目 / 操作 / 人过滤
├─ 项目设置              配额 · 默认网络 · 默认模板与规格 · 保留期
└─ 运维(仅 operator)     节点与容量(排空、均衡、cordon、预览)· 平台审计与哈希链 · 告警状态 · 价目表 · 租户(账户)
```

角色:**成员**(建与用沙箱)、**owner**(改配额、批放宽、管成员与密钥)、**viewer / billing**(只读;能看账单)——后两个是新增,Daytona 的 `read:billing` 给了启发,现在只有 owner / member 两级;**operator**(部署者,看运维区)。

## 5. 关键页面

每页的线框见对话里的三张图(概览、沙箱详情、用量与账单)。要点:

### 概览
四块数字(今天花费 / 预算、运行中沙箱、容量、等批的放宽)+ 24 小时的运行数与花费曲线 + 运行中沙箱的前几条 + 最近的事。**没有任何沙箱时**整页换成上手引导:三步(拿密钥 → 装 SDK / 加 MCP → 跑一段代码),代码块里 URL、项目、密钥占位已经填好,能复制。

### 沙箱列表
列:状态点、id / 名称、模板、类别与优先级、节点、内存、已运行时长、今天花费、标签。顶部:搜索框(id、标签、模板)、过滤胶囊(状态、类别、节点、标签)、保存的视图。勾选后批量:暂停、删除、打标签、延长 TTL。SSE 推送变化,新出现的行高亮一下。

### 沙箱详情(重点)
头部:id、状态、节点、一排主操作(暂停 / 恢复 / fork / 检查点 / 删除),**等价调用**折叠区。标签页:

| 标签 | 内容 | 后端 |
| --- | --- | --- |
| 概览 | 规格、模板、层、env 键、TTL 与保留期、标签、花费 | 已有 |
| **指标** | CPU、内存、盘、出站的曲线,1 小时窗口,5 秒一个点;与计费口径一致 | **新**:节点按沙箱采样的环形缓冲 + 接口 |
| 终端 | 现在在右栏的终端与执行,搬进来 | 已有 |
| 文件 | 文件树与预览 | 已有 |
| **网络** | 当前策略;**最近 200 条出站决定**(放行 / 拒绝、命中哪条规则、注入了什么凭证);改策略时显示"这是放宽,需要 owner 批"并走审批 | 已有(`/egress`、`/network/requests`),界面里没用上 |
| 检查点 | 时间线,回滚前预览"会丢掉之后 N 分钟的改动";从这里 fork | 已有 |
| 端口与卷 | 暴露的端口地址与"试一下";附着的卷 | 已有 |
| **事件** | 事件日志(model_call、report、note、checkpoint)与这台沙箱相关的审计行 | 已有(`/events`、`/audit`) |

### 用量与账单
折线 / 堆叠面积:按小时或天;切换"按沙箱 / 按标签 / 按类别(vcpu、内存、盘、出站、模型 token)";右侧预算条与阈值(75% / 100% 提示);下方结算列表与 CSV。点任何一段下钻到沙箱列表的同一过滤。

### 成员与密钥
成员:邀请(生成一次性链接,不再是"抄令牌")、角色、有效期。**API 密钥**:创建时填名字、过期、**范围**(只读 / 本项目 / 某些操作),创建者给不出自己没有的范围(学 Daytona);表格有最后使用时间与来源;一键撤销;管理密钥可派生子密钥(第二期)。

### 运维区(仅 operator)
节点卡片(存活、负载、内存、沙箱数、cordon 状态)+ 容量曲线;**排空 / 均衡前给预览**("会搬走这 6 台,目标节点 X、Y");平台审计与"核对哈希链";告警当前状态(读 `/metrics` 的依赖与失联指标);价目表;账户与租户。

## 6. 关键流程(要走通的)

1. **新租户第一次**:收到邀请 → 概览空状态 → 创建密钥 → 复制 SDK 代码 → 在本机跑 → 概览出现第一台沙箱。
2. **调试一台沙箱**:列表搜索 → 详情 → 指标看内存涨 → 网络标签看被拒的域名 → 终端进去查 → 打检查点 → 修 → 回滚预览确认。
3. **批一条放宽**:概览上"1 条待批" → 看清"新放开的是这三个域名" → 批准 / 拒绝并写原因。
4. **查一笔贵的账**:用量曲线某天凸起 → 按标签拆 → 下钻到沙箱 → 看它的指标与事件。
5. **operator 处置失联节点**:概览红条"2 台在失联节点上" → 运维区节点卡片 → 确认节点已死 → 接管预览 → 执行 → 看 moved / lost。

## 7. 后端要补什么

| 需要 | 现状 | 工作量 |
| --- | --- | --- |
| 沙箱列表的 SSE 推送 | `/events/stream` 已有,只发"这类对象变了" | 小:前端订阅后重拉 |
| 出站决定、事件、审计的展示 | 接口都有 | 纯前端 |
| **用量时间序列**(按小时 / 天,按沙箱 / 标签 / 类别) | `usage_events` 有全部原料(含 `meta`),缺聚合接口 | 中:一个 SQL 聚合接口 + 标签写进事件 |
| **每沙箱实时指标** | 节点有 `disk_used_mib`、`egress` 的此刻值,没有 CPU / 内存 / 历史 | 中:节点读 cgroup 的 `cpu.stat`、`memory.current`,环形缓冲(1 小时 / 5 秒 / 每台约 720 点),`GET /sandboxes/<id>/metrics` |
| **API 密钥**(命名、过期、范围、撤销、最后使用) | 只有成员令牌 | 大:新表、解析与范围执行、创建者不越权、审计;这也是 013 里"范围令牌"那条残余风险 |
| 角色 viewer / billing | 只有 owner / member | 小到中:角色枚举与各路由的检查 |
| 构建日志流 | 没有(D37 的"没做的") | 中 |
| 模板"就绪 / 健康" | 有构建状态与快照是否存在,没有健康检查 | 小到中 |
| 邀请链接 | 没有 | 小:一次性令牌 + 过期 |
| 预算阈值提醒 | 只有每日上限(超了 402) | 小:阈值事件进审计与概览 |

## 8. 前端怎么做

- 沿用现有技术(React + TypeScript + Vite、插件内核、设计系统 `DESIGN.md` 与机检脚本),不另起炉灶。
- **新外壳**:`#/console/…` 一组路由,自己的布局组件与导航,从插件内核注册;agent 工作台保持原样,两边用应用切换器互通。现在的 `cloud`、`sandboxes`、`nodes` 三个插件的内容**搬进新壳**,不重写已有的表格与表单。
- 图表:手写 SVG 的折线 / 面积 / 迷你图组件(不引入图表库;几百个点够用),配色遵循现有设计令牌。
- 通用组件:带过滤胶囊的表格、命令面板(⌘K)、"等价调用"折叠块、空状态引导块、预览对话框。
- 国际化:先把文案抽成字典、默认中文,英文作为第二语言;这一步越晚越贵。
- 回归:每期用 Playwright 截图与现在的 11 张对比,单个组件有 vitest。

## 9. 分期

| 期 | 做什么 | 新后端 | 你能看到的 |
| --- | --- | --- | --- |
| **P0** | 独立外壳 + 项目切换 + 按角色的导航;把现有页面搬进去 | 无 | 控制台脱离 agent 应用;owner 不再看到 403 页 |
| **P1** | 沙箱列表(搜索、过滤、批量、SSE)与带标签页的详情(网络决定、事件、检查点预览) | 无 | 排查一台沙箱不再靠猜 |
| **P2** | 用量与账单(曲线、拆分、预算条)+ 概览的曲线与上手引导 | 用量聚合接口、标签写进事件 | 能回答"钱花哪了" |
| **P3** | 每沙箱实时指标 | 节点采样与接口 | 详情页有 CPU / 内存 / 盘 / 出站曲线 |
| **P4** | 成员与密钥(邀请、命名、过期、范围、撤销)、viewer / billing 角色 | 密钥表与范围执行 | 外部团队能拿到只读密钥 |
| **P5** | 运维区(排空 / 均衡 / 接管预览)、模板健康与构建日志、英文 | 构建日志流、模板健康 | operator 有自己的家 |

P0 到 P2 不碰节点与合同的核心路径,风险最小;P4 动安全边界,要单独评审。

## 10. 要你定的

1. **控制台从 agent 工作台里分出来,独立成壳?**(我建议是;代价是两个入口要维护切换。)
2. **英文界面**:现在就抽字典,还是等 P5?(我建议 P0 就抽字典,文案不多时改成本最低。)
3. **P3 和 P4 谁先**?指标是排障的体验,密钥是外部团队能不能上手的前提。(我建议密钥先:没有它外部团队只能用成员令牌,013 里这条是残余风险。)
4. **图表**:手写 SVG,还是引入一个小库(uPlot 约 45 KB)?(我建议手写,先够用。)
5. **角色**:现在两级加 viewer / billing,还是先不加?(我建议 P4 一起做。)
6. **视觉**:沿用现在的设计令牌与风格,只改信息密度与排版;还是借这次换一套视觉?(我建议沿用。)
