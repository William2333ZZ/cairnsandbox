## 还缺的输入(没有它定不了真价格)

1. **我们的真实成本**:一台 192 核 / 8×4090 的机器折旧加电费加机房,按"可售 vCPU·小时"摊(要看内存超卖比与 `VCPU_OVERCOMMIT`)。没有这个数,就不知道平价是赚还是亏。
2. **计费口径**:默认按**分配**的 vCPU / 内存计(同 E2B / Daytona)。Vercel 按**活跃 CPU** 计,对"大部分时间在等模型回复"的 agent 沙箱便宜得多——D67 已经把 `vcpu_active_s` 做成可选的第二种口径(默认价 0 = 不记);**没做的是数据**:要先量一批真实 agent 负载的 CPU 空闲占比,才知道活跃 CPU 的单价该定多少。
3. **套餐**:E2B 的 $150 / 月 Pro、Modal 的 $30 / 月额度、Daytona 的 $200 注册额度说明主流是"按量 + 起步额度"。我们已有邀请码带起步额度(D60)和预付(D59),月费套餐没做。
4. **免费额度的滥用成本**:Daytona 送 $200 之所以敢,是有风控;我们的试用额度要和滥用检测(D58)一起看。
