## 1. 现在的位置

能给**自己人和可信团队**用;不能给**陌生人、公网、付费客户**用。差的不是功能数量,是"敢让陌生人付钱用"的那一层:隔离证据、滥用治理、高可用、收款、对外接入面、合规。

我们有而竞品公开能力里没有同等物的:检查点 / 回滚 / fork(迁移时带状态)、带审批流的 L7 出口策略与凭证注入、哈希链审计、按项目计量与账单、多租户控制台。商业化要**守住这几样**,不去追每一项竞品功能。

## 3. 路线(按顺序;每步可独立交付)

**阶段 A:把底座做牢(自己人可信 → 小范围外部内测)**
1. **S3 兼容对象存储接 fc-store(G3)** — 本窗口第一件。选型见下节。
2. 滥用治理(G2):出口与 CPU 异常检测、账户一键冻结、新账户限额、配额升级审批。
3. 节点故障自动接管(G4):心跳丢失 → 栅栏(先确认旧节点停止)→ 从最近检查点恢复。先做"检测 + 建议",再做自动。
4. 威胁模型落地清单(G1):逐条对照缓解措施与测试,缺的补上;列出需要外部评审的项。

**阶段 B:让人愿意上手**
5. JS/TS SDK(G7),与 Python SDK 对齐;E2B 兼容层范围写死在矩阵里。
6. 公网预览域名(G7):`<port>-<sandbox>.<域名>` 的 HTTPS 反代,走项目鉴权或公开开关。
7. 命名 API 密钥 + viewer/billing 角色(G9)。
8. 实时指标(节点侧环形缓冲)与构建日志(G8)。

**阶段 C:收费**
9. 套餐/预付额度/发票;支付对接(G6)。
10. 状态页、SLA 草案、DPA 模板(G10)。

阶段 C 之后才考虑:多区域、SSO/SCIM、SOC2、GPU/桌面模板。

## 4. S3 兼容存储选型(G3)

要求:单机先跑、能扩成多副本;S3 API;许可证能接受;镜像能在本机受限出口下拉到;运维简单。

| 选项 | 优点 | 问题 |
| --- | --- | --- |
| **Garage**(Rust) | 单二进制、资源省、为小集群设计、多节点复制、S3 API 够用 | AGPLv3(自己部署、不修改分发则无碍);无 S3 版本化 |
| MinIO | 事实标准、功能全 | 本机镜像拉取失败(镜像源返回 HTML);近年社区版功能收缩、AGPL |
| SeaweedFS | 功能多 | 组件多(master/volume/filer),运维重 |
| Ceph RGW | 生产级 | 对当前规模过重 |

**选 Garage**:镜像已能拉取;一个容器 + 一个 toml 就能跑;以后加节点只需改布局。fc-store 不直接暴露 S3,而是在 `imgstore.py` 里加 **S3 后端**:对节点和控制面仍是现在的 HTTP 接口(零改动),只是落地从本地目录换成桶。这样回退只需改一个启动参数。

**可推翻条件**:若 Garage 在小对象(1 MiB 块)高并发读上延迟明显不如本地盘,保留本地盘作为读缓存层(节点侧已有懒加载缓存,先量再定)。

## 6. 需要你决定或提供的(我不能替你做的)

1. **升级盒子上的节点镜像**:实时指标、构建日志、自我围栏都在节点里,盒子上的 `fc-node` 还是旧镜像。升级要重启节点容器(会中断上面的沙箱),属于你来点头的操作。CI 的测试集群(fc-node-2/3)会用新镜像,test-cp 里有一步专门验指标。
2. **真实硬件成本**:没有它定不了价(见 [定价对照](pricing-2026-11.md))。
3. **支付服务商账号**:接 Stripe 之类需要真实账号与密钥;我已把控制面做成"只收 webhook 调 `/credit`",密钥不会进控制面。
4. **一台能断网的机器**:围栏与自动接管要在真实网络分区上演练一次才能打开。
5. **外部渗透测试**:T1 的缺口,只能找人做。
6. **域名与 TLS**:预览域名要通配 DNS + 证书(前面放 Caddy / nginx),状态页要有一个独立于控制面的托管。
