# 001 用户使用过程

本文从用户的一天写起:一个人怎样得到自己的 agent、把事交给它、走开、被它找回来、教它例行、看着它变强。它建立在 [000 原则](000-principles.md) 之上;后面的每一篇文档都是这个过程里某一段的实现,实现里的概念在 002 定义,这里只用用户自己会说的词。

产品的定义就是这个过程,不是部件清单。一个部件的存在理由必须能指到下面某个阶段里用户看到或得到的东西;指不到的,不做(000:尽量少做产品)。

## 用户是谁

- **一个开发者**。有自己的仓库、代码托管账号、聊天工具,有一堆想交出去的事:修这个 issue、把 CI 弄绿、给这段代码补测试、每天早上看一遍昨晚的告警。他不想盯着,也不想换工具。
- **平台自己**。它把"让 agent 在我的任务上做得更好"这件事也当成一个用户交出去的事:评测、迭代、失败的任务,都走同一条路进来(000:评测只回答产品问题)。

部署这个平台的人是第一个用户,他能给别人开账号;每个用户一个 agent。团队是清单上的事,不是另一个产品。

## 一个 agent 是什么样

每个用户有**一个** agent。它不是一次会话,是一个持续存在的东西:

- 有名字和身份:在用户的代码托管与聊天工具里以自己的账号出现,签自己的名,不冒充用户。
- 有自己的电脑:做事的时候在云上的隔离机器里做,用户的笔记本合上它还在。
- 有记忆:记得用户的偏好、做过的事、正在做的事、手里的文件;下一件事从这些记忆开始,不是从零开始。
- 有预算和边界:每天能花多少、能碰哪些仓库、什么动作要先问。都是用户定的,平台强制(000:边界靠权限)。
- 会变强:它的运行系统在用户的任务上被测、被改、被换;对用户这像一次应用更新,附一句"改了什么、在你的事上好了多少"。

用户看到的只有这一个 agent。它背后同时开几台机器、派了几个帮手,是实现,不进用户的视野。

## 十个阶段

每个阶段写三件事:用户做什么、agent 做什么、用户什么时候会被打扰。打扰只有三种理由:**做完了、卡住了、要你做决定**。此外一律安静。

### 1 拥有

用户登录,得到自己的 agent。第一屏是一段空的对话,和一句话:这是你的 agent,告诉它一件事,或者先把它接进你用的地方。

没有向导、没有设置页。预算有默认值(每件事 1 美元;**它自己发起的事——CI、例行、评测——每天合计 5 美元**,到了就先停着,你开口要的事不受这个限制),边界有默认值(只读外部网络、只碰接入的仓库),都能在对话里改。对话输入框旁边一直写着"今天花了多少 / 上限"。

### 2 接入

用户把 agent 接进自己已经在用的地方:

- **代码托管**(Gitea 与 GitHub,同一组方法;部署时选一个):agent 以自己的账号加入仓库,从此 issue 和评论里 @ 它就是在跟它说话,它开 PR、回评论用自己的名。
- **聊天工具**(飞书、Slack 或通用 webhook,按文档对接,未经真实联调):同样以自己的账号出现在用户的私聊和群里。
- **用户自己的工具**(还没有):agent 要用的登录态与密钥由用户交给平台保管,agent 做事时经平台代为使用,从不拿到原文(000:凭证不进沙箱)。

接入是一次性的;接入了什么,在对话里问它就能得到清单。

### 3 交代

用户在对话里说一句话,或在 issue 里 @ 它。手机、桌面、聊天工具,哪里说都一样,是同一段对话。

agent 回一句"接到了,我去做",然后开始。它不复述任务、不列计划让用户确认(要确认的事它会在卡住时问)。一句话可以是一件事,也可以是几件;agent 自己拆。

### 4 走开

用户关掉页面、合上电脑。agent 继续做:在自己的机器上改代码、跑测试、看结果。做完一件事机器就还回去;下一件事从记忆和仓库的现状开始。

用户回来打开对话,看到的是一条时间线:它什么时候开始、现在做到哪、花了多少;展开能看每一步的命令与输出。看不看都行,不看也不影响它。

### 5 被找

agent 只在三种情况主动找用户,通过用户在哪就发到哪(对话、issue 评论、聊天工具):

| 情况 | 它说什么 | 用户要做什么 |
| --- | --- | --- |
| 做完了 | 一句结果,附可以验收的东西:PR 链接、改动摘要、测试结果 | 看一眼;合并或退回 |
| 卡住了 | 一个具体的问题,附它已经试过什么 | 回答一句 |
| 要你做决定 | 一个将要发生的不可逆动作的**草稿**:要合并的 PR、要发出去的消息、要超出预算的花费 | 同意或否决;不回答就不发生 |

进度、中间结论、"没有新进展",都不说。一件做了一天的事,一天一句就够。

同一件事它不重复问;用户答过的,它记住。

什么时候该问、什么时候该自己定,是它的能力,不只是礼貌:问了不该问的(打扰)和没问该问的(擅自假设)都在它的评测里计数(第 10 阶段)。它知道什么时候该问你,问得准不准也在被测。

### 6 纠正

agent 干活的时候用户随时可以插话:"不对,先别改那个文件"、"周四再做"。插话优先于它排着的工作,它当前这一步做完就看到,改方向或停下。"停"是立刻停,不问为什么。

连着说的几句话它合起来理解,不会把"检查这个线程"和紧接着的"周四再做"当成两件事。

纠正不是说过就完:它成为记忆里的一条规则(第 9 阶段),也成为以后它必须通过的一道考题(第 10 阶段)。用户纠正过一次的事,下一次不该再错;再错了,是它的运行系统该改。

### 7 教它例行

用户说"以后每天早上八点,把昨晚的 CI 失败整理给我",agent 把它存成一条**例行**,复述一遍,用户点头后生效。例行到点自己醒来做,做完按第 5 阶段的规矩找用户。例行的清单在对话里能问到,能改、能停。

新建例行要用户点头,因为它会在用户不在的时候花钱、动仓库。

### 8 它自己来活

接入之后,有些事不用用户说,agent 自己醒:

- 仓库的 CI 在主分支上红了。
- 它开的 PR 有人评论了、被退回了。
- 它自己的评测发现它在某类任务上退步了。
- 一条例行到点了。

这些事进来和用户交代的事一样处理;用户看到的是对话里多了一段"我发现……,已经在做",之后按第 5 阶段的规矩安静。

### 9 它记得你

agent 的记忆分四层,用户不用管,但能看到、能改、能删:

- 稳定的偏好:语言、常用的技术、长期的要求。
- 带日期的日志:什么时候做了什么。
- 当前的工作笔记:目标、进度、决定、卡点。
- 文件与证据:它改过的代码、读过的文档、跑过的结果。

记忆是信息,不是命令:记忆里写着"用户喜欢 X"不等于用户现在让它做 X。用户纠正过的事进记忆;用户说"忘了这个",就删。

记忆的好坏只按一件事衡量:同一个用户的下一件事,做得比上一次好。记得多少不算,背得全不算;记了却没让下一次更好的东西,是该剪掉的。

### 10 它变强

agent 的运行系统在用户的任务上被不断评测和改进。用户偶尔在对话里看到一条更新,它能回答四个问题——改了什么、为什么改、在你的哪些事上好了、怎么退回去:"我的运行系统更新了:改了观察输出的格式,因为你上周三次退回的 PR 都是没看全测试输出;在你最近 30 件事上的成绩从 0.71 到 0.82,花费少了四分之一;回复'退回'就回到上一版。"没有变好的改动用户看不到。用户可以退回上一个版本。

考题里有三种是从这个用户身上来的:前面做过的事里有可复用知识的(看它是否记住了);埋着只有做下去才碰到的障碍的(看它该问时问了没);要做很久的(按子任务给部分分,不是只看最后成不成)。

评测用的任务来自用户自己交过的事(000:任务来自用户自己的工作),不是公开题库;公开题库只做回归。

## 多个 agent 与团队

一个用户可以给不同岗位开不同的 agent(修 bug 的、看告警的):各有自己的事、例行和记忆,共用机器与仓库;在对话里写"@名字 ……"就交给它。团队 = 部署者开的几个用户共用一个部署(代码托管归部署者)。agent 之间也能传活:一个 agent 把事交给另一个(`HANDOFF`),一次一个所有者、最多三跳、不成环,接收者的话回到原来的地方(接缝的定义在 002 的 Handoff)。

## 我们与 Grok Bot 一类的差别

上面的过程和 Grok Bot、Cursor 的 always-on agent 一致([调研](research/always-on-agents.md));2026 年的同类产品与学术结论、以及由此定下的方向,在 [另一篇调研](research/landscape-2026-11.md)里。三处不同,是有意的:

- **它们每个用户一台电脑,我们每件事一台隔离机器**,一个用户同时很多台。好处是隔离与并行,代价是记忆和登录态不能靠"同一台机器"自然延续,必须由平台显式提供(第 2、9 阶段)。
- **它们的 agent 不改自己,我们的会**(第 10 阶段)。所以 000 的原则对我们是硬约束:agent 报的一切都不可信,成绩只能在它之外测。
- **我们先做代码的事**。现在的"事"几乎都落在仓库里:交付物是 PR,验收是 CI 和人的 review。桌面与浏览器操作还没有。

## 不分期

十个阶段都是产品的一部分,没有"第一期做哪些"。一次做一件事,做完一件(代码、测试、部署、真实走一遍、文档)再做下一件;顺序在 011 的工作清单里——按"用户下一次打开工作台最先感觉到什么"排,不按部件。多用户、聊天工具、团队不是以后的期,是清单上靠后的事。

## 尚未实现

逐阶段的现状(D17 之后;"真实"指在开发机上用真实模型走过):

- **1 拥有**:登录是一个令牌;部署者能新建用户,每个用户有自己的 agent(对话、例行、记忆、策略);预算与边界在策略里,还没有对话里改的入口。
- **2 接入**:代码托管(Gitea,GitHub 同形)与聊天工具(飞书 / Slack / 通用 webhook)都能接,凭据在宿主侧;用户自己的工具登录态还不能交给平台保管。
- **3 交代**:工作台对话、Gitea @ 都进同一段对话,接到后回一句确认。
- **4 走开**:做事在隔离机器里,服务常驻;回来能看时间线和每一步;harness 停在步数或时限上不再沉默,会说"停下来了,要继续吗"。
- **5 被找**:做完、卡住、要决定三种进对话并送回来处;合并是草稿,草稿到面前之前先经独立审查(密钥、CI 路径、删测试、测量代码、不可信来源),拦下的要再确认一次;浏览器通知有了;该问就问有真实使用里的读数(`/ask`)。**真实走过**:改评测器的 PR 带着"改到了测量代码"的提醒到了面前。agent 遇到缺信息的请求,真实上多半不问而是翻代码翻到步数用完(见 D18):尺子有了,agent 的这项能力还没有。
- **6 纠正**:插话能打断进行中的模型调用;"停"立刻生效;连句合并有;纠正(插话、带理由的否决、关 PR、停止)被认出,有话的提炼成一条规则,对话里一句"记住了"并可当场"忘了这条",下一件事开始时带着,之后合并的 PR 成为带规则的依赖题。**真实走过**:一次纠正、一次带理由的否决,各得一条规则,下一件事果然照做。
- **7 例行**:对话里说的重复的事会成为草稿,同意后定时发单;只认"每天 + 时刻 / 每 N 分钟"。
- **8 它自己来活**:CI 红、评测退步、例行到点三种已经会醒;PR 被评论会醒;CI 同时只开一张单。
- **9 它记得你**:五层记忆(偏好、日志、笔记、文件与证据、纠正得来的规则),派工前读、派工后写;平台自己干的活不进别的事的记忆;规则按仓库隔离。还没有按"下一件事好了多少"在线衡量(离线有依赖题与对照臂),也没有剪枝以外的老化。
- **10 它变强**:评测与改进在跑;被接受的版本以一段话更新到对话:改了什么、为什么、按类别(普通、依赖、要问、做得久)在你的事上好了多少、该问就问的 F1、预计与实际、怎么退回;候选带改动清单,丢掉稳定通过的不接受;考题有四种,并能从仓库自己的提交历史批量挖出。还没有:用户任务集里的依赖题与障碍题要靠真实纠正与真实提问积累,现在很少。
- **多个 agent**:可开按岗位命名的 agent;"@名字"或"交给 名字"直接送去;agent 自己也能 `HANDOFF` 把事交给另一个(一个所有者、最多三跳、不成环、不交给自己、不可信的话仍不可信、结果镜像回来)。**真实走过**:主 agent 两次自己把小改动交给了 fix,fix 做完、开了 PR、批准草稿在 fix 那里等,结果也留在了主 agent 的对话里。
